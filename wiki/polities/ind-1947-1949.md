## Sugar data diagnosis

Reported aggregate sugar=1,589,393,500 tonnes (n4) is a pipeline display artefact in territorial_flagged.json, NOT a production data error.

Root cause: the staples() function in pipelines/polity-autoimprove/02_territorial_evidence.py matches all items containing "sugar" and all units containing "tonne", then computes a single median across the mixed series without separating by unit first. The 4 matched rows for IND-1947-1949 are: mitchell sugar cane 3,176,000 t (1948) and 3,221,000 t (1949) in actual tonnes; fao1952 centrifugal/non-centrifugal cane sugar 1,255 and 2,787 in "1000 tonnes". Sorted: [1255, 2787, 3176000, 3221000]. Median = (2787+3176000)/2 = 1,589,393.5. The unit mode() returns "1000 tonnes" (alphabetically precedes "tonnes" in a 2-2 tie), so the scaling logic multiplies by 1000 yielding 1,589,393,500.

The underlying source values are correct: Mitchell sugar cane ~3.2 Mt/yr (plausible); FAO 1952 centrifugal 1,255,000 t + non-centrifugal 2,787,000 t = 4,042,000 t total (consistent with late-1940s India). No correction to before_1961.csv or any production dataset is required.

The earlier wiki note "Sugar unit-label display bug in pipeline noted and fixed in code" was premature — the scaling logic existed but the cross-unit mixing was not corrected.
