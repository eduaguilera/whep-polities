# Belgium-Luxembourg

## Summary

> **`polygon_status` migrated derived -> assigned (2026-07-29).** `derived` is a legacy value that predates the documented vocabulary in [wiki/README.md](../README.md#page-schema), which says not to use it in new pages. It was never migrated, so the manifest's `claims_polygon_status` set omitted it and consumers were told this row does not claim a polygon. The polygon is composed from its members by `scripts/sources/reporting-areas/build.py`, so it IS this row's territory by construction. See [lint-polygon-status-vocabulary](../log.md#lint-polygon-status-vocabulary).


WHEP aggregate reporting-area row for FAOSTAT/FABIO area code 15, Belgium-Luxembourg. This is not a country row; it is a data reporting unit used when source data combine Belgium and Luxembourg. The 1850-1999 range follows the current WHEP primary-production and land-footprint rows; detailed trade rows using the same reporting area are observed for 1986-1999.

## Territorial Extent

- **Polygon source:** derived WHEP `reporting-areas` source.
- **Components:** Belgium and Luxembourg current GADM 4.1 adm0 polygons.
- **Proxy note:** The polygon is a current-territory union for spatializing this aggregate reporting row; it does not imply a single sovereign polity.

## Predecessors and successors

- **Successors:** [[bel-1831-2025]] and [[lux-1839-2025]] — see
  [bel-1831-2025.md](bel-1831-2025.md) and [lux-1839-2025.md](lux-1839-2025.md).
  Added 2026-08-13 (issue 138). This row is a *reporting union*, and the members it
  aggregates are exactly its territory; when the union stops being reported the data
  routes to the two members. FAOSTAT itself split area 15 into 255 Belgium and 256
  Luxembourg from 2000, which is where `end_year = 1999` comes from, so the split is
  datable and not a judgement call.
- **Convention followed:** the same one already used by the other combined reporting
  units — `SYL-1944-1953` declares `successor: [SYR-1946-1967, LBN-1944-2025]`,
  `F249-1918-1990` declares `YEM-1990-2025`, `F237-1954-1975` declares
  `VNM-1975-2025`. Before this change `BLX-1850-1999` was the only combined *union*
  row declaring neither a predecessor nor a successor, so a consumer walking
  `successor` could not tell "Belgium-Luxembourg has no successors" from
  "its successors were never recorded".
- **No reverse edge, deliberately.** Neither Belgium nor Luxembourg names this row in
  `predecessor`; both correctly name `NLD-1800-1830`, the actual state succession.
  Nothing in this database declares an aggregate as *its* successor — an aggregate is
  not what a territory *became* (see the 2026-08-13 note in
  `scripts/validate_chain_integrity.py` on `F206-2011-2025`, where adding the reverse
  edge broke whep's `.bucket_is_predecessor()` exact-set comparison). `SYL-1944-1953`
  is asymmetric in exactly this way for exactly this reason. The cost is two more
  successor-only edges in that gate's asymmetry count, which is the correct trade.
- **No predecessor:** the union has none. Its members' shared predecessor
  `NLD-1800-1830` ends in 1830, twenty years before this reporting row starts, and the
  union is a statistical artefact rather than a territorial successor of the United
  Kingdom of the Netherlands.
