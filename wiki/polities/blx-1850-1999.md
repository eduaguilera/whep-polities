# Belgium-Luxembourg

## Summary

WHEP aggregate reporting-area row for FAOSTAT/FABIO area code 15, Belgium-Luxembourg. This is not a country row; it is a data reporting unit used when source data combine Belgium and Luxembourg. The 1850-1999 range follows the current WHEP primary-production and land-footprint rows; detailed trade rows using the same reporting area are observed for 1986-1999.

## Territorial Extent

- **Polygon source:** derived WHEP `reporting-areas` source.
- **Components:** Belgium and Luxembourg current GADM 4.1 adm0 polygons.
- **Proxy note:** The polygon is a current-territory union for spatializing this aggregate reporting row; it does not imply a single sovereign polity.

## Sourced Claims

- `inst/extdata/regions.csv` in WHEP records `BLX`, area code 15, as Belgium-Luxembourg.
- `inst/extdata/harmonization/regions_full.csv` marks this as a CBS reporting row.

## Polygon status consolidated (added 2026-07-28)

`polygon_status` changed from `derived` to **`assigned`** in the polygon_status
vocabulary consolidation ([log lint-consolidate-polygon-status](../log.md#lint-consolidate-polygon-status)).

`derived` described *how* the polygon was made — by the `reporting-areas`
builder — rather than what it claims, and it was not one of the values
`scripts/validate_polygons.py` check C recognises, so this row could have
declared a polygon it did not have and nothing would have failed. It does have
one: the attached geometry measures **33,344 km2** in an equal-area projection
(Belgium plus Luxembourg, against the 33,114 km2 sum of the two modern territories). That geometry *is* this reporting area's territory rather than a
stand-in for another entity, which is what `assigned` means. The row is now
covered by check C, and by check A whenever `polygon_area_km2` is filled in
(it is currently null, so the area comparison is skipped). The builder
provenance is unchanged and stays documented under Territorial Extent.
