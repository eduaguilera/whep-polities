# Eure

## Summary

Eure is a French département in the Normandie region, occupying the eastern part of historic Normandy between the Seine valley and the Île-de-France border, with its préfecture at Évreux. It is coded `subnational` because a département is an administrative subdivision of France, not a sovereign or internationally distinct territory: French sovereignty over this area is continuous and undisputed across the whole entry span, and that sovereignty claim is already carried by the national FRA rows in this table (FRA-1800-1871, FRA-1871-1919, FRA-1919-2025). This entry exists purely to give a home to sub-national reporting-territory data — statistics keyed to "Eure" or its Eurostat NUTS3 code FRD21 — which cannot correctly be routed to a national French row roughly fifteen times its size. The entry follows the country's default start rule for an original Revolutionary département (1790), adjusted to 1800 to match the earliest available FRA container row (see decisions), and runs to the open end_year 2025 since the département remains an active, unaltered administrative unit of France today with no predecessor or successor.

**Why this entry exists.** This entry captures juan-subnational source data for unit FRA-FRD21 (Eure, NUTS3 code FRD21, INSEE department code 27). Prior to this decision, the underlying rows had no polity to route to at all — the routing pipeline's match_existing search returned zero name candidates and zero boundary matches against the existing FRA table, because the only FRA rows present are the three national chain entries (FRA-1800-1871, FRA-1871-1919, FRA-1919-2025), each of which represents the whole country rather than any single département, so matching this sub-national series to any of them would have silently conflated department-level statistics with all-France totals roughly fifteen times larger. What confirms Eure as a distinct, separately-tabulated entity rather than an arbitrary subdivision invented for this pipeline is that it is one of the original ~83 départements created by the 1790 Revolutionary administrative reform and has been continuously enumerated under INSEE numeric code 27 in French national statistics, while independently carrying Eurostat NUTS3 code FRD21 in EU regional statistics — the same dual-apparatus evidence already used to justify sibling entries FRA-14, FRA-18, FRA-21, FRA-25 and FRA-28. The routing decision records that none of the four documented country-convention departures (Belfort, the Alsace-Lorraine trio, the Corsican split, overseas departments) apply to Eure, so the default start rule governs and this is a plain create_new case rather than a boundary-change edge case.

## Territorial extent

**Polygon status:** Not yet assigned. No polygon available in the GeoPackage for this period. The routing evidence classifies this as `new_source_needed`: GADM 4.1's global ADM1 release covers French départements at the correct administrative level and would use the same id_column (GID_1) as the already-registered gadm-4.1-adm1 source, but the file actually present in this repository is a curated 81-country subset that omits France entirely. cshapes-2.0 and cshapes-europe, already used to build the FRA national polygons, are country-level only and carry no internal French subdivisions. No registered, locally-present source can construct this polygon by union or difference either. This is the same gap already recorded on sibling entries FRA-14-1800-2025, FRA-18-1800-2025, FRA-21-1800-2025, FRA-25-1800-2025 and FRA-28-1800-2025.

**Territory description:** Eure occupies the eastern Normandy plateau along the lower Seine, bordered by Seine-Maritime to the north, Île-de-France (Yvelines, Val-d'Oise, Eure-et-Loir) to the east and south, and Calvados/Orne to the west; its préfecture is Évreux, and its largest town is Vernon on the Seine near Giverny. A reader can locate it on a modern map as the département immediately southwest of Rouen and northwest of Paris, straddling the A13 motorway between the two cities. Its area is approximately 6,040 km2 (a published administrative figure for the current département, not a measurement from any geometry attached to this entry, since none is attached yet) — this is INSEE's own stated area for département 27, not a figure derived from the GeoPackage.

## Predecessors and successors

Eure has no predecessor or successor polity in this database: it is one of the original ~83 départements created by the 1790 Revolutionary reform, assembled largely from the former province of Normandy (parts of the généralités of Rouen and Alençon), and it has never been abolished, split, or merged into another unit. Its administrative boundaries and its INSEE numeric code (27) have remained stable since creation. It sits alongside sibling entries FRA-14-1800-2025 (Calvados), FRA-18-1800-2025 (Cher), FRA-21-1800-2025 (Côte-d'Or), FRA-25-1800-2025 (Doubs) and FRA-28-1800-2025 (Eure-et-Loir) as another French département given its own row for the same reason: reporting-territory data keyed to the département, not the nation, needs a home that isn't the FRA national chain.

## Decisions

### d-start-year-1800-not-1790

**Start year set to 1800, not the 1790 creation date, to match the earliest FRA container row**

The country convention's default start rule for an original Revolutionary département is 1790, the year Eure was carved from parts of the former province of Normandy (the généralités of Rouen and Alençon). But the earliest national FRA row in this database, FRA-1800-1871, begins at 1800, and the containment gate rejects an edge that starts before its container's own span begins. Rather than leave 1790-1800 uncontained, this entry's start_year is set to 1800 to match the available container, following the same adjustment already made for sibling entries FRA-18-1800-2025 (Cher), FRA-28-1800-2025 (Eure-et-Loir), FRA-77-1800-2025 and FRA-91-1968-2025. The polity_code years (1800-2025) equal the frontmatter years as the gate requires, and this departs from the routing decision's own proposed start_year of 1790 for exactly the containment reason stated above.

### d-numeric-code-27-not-frd21

**Code uses the INSEE numeric département code (27), not the routing unit_id FRA-FRD21**

The routing decision names the unit FRA-FRD21 using its Eurostat NUTS3 code, but the dominant pattern for FRA subnational rows already in this table (FRA-14, FRA-18, FRA-21, FRA-25, FRA-28) keys on the INSEE numeric département code rather than the NUTS3 identifier, because INSEE's own code is the one under which French statistical series have been tabulated since the département's creation and is more legible to a reader than a Eurostat identifier. Eure's INSEE code is 27, giving FRA-27-1800-2025. This keeps the new entry consistent with its siblings rather than introducing a second FRA subnational naming scheme.

### d-polygon-left-unassigned

**Polygon left unassigned rather than constructed from an unregistered source**

The routing decision's polygon_route is new_source_needed: GADM 4.1's global ADM1 release covers French départements at the right admin level, but the locally registered gadm-4.1-adm1 source is a curated 81-country subset that excludes France entirely, and no other registered source (cshapes-2.0, cshapes-europe) carries subnational French boundaries. Rather than fabricate a polygon reference to a source not present on disk, this entry ships with polygon_source: none and polygon_status: unassigned, matching the identical situation already recorded on FRA-14, FRA-18, FRA-21, FRA-25 and FRA-28. Fetching and registering the GADM 4.1 global ADM1 release (or an IGN ADMIN-EXPRESS historical département layer) is future work, not something this page can resolve.

## Open questions

### oq-department-boundary-stability-1790-1800

**Whether Eure's boundary changed between its 1790 creation and this entry's 1800 start**

This entry starts at 1800 to match the earliest available FRA national container row, ten years after the département's actual 1790 creation. It is not yet confirmed whether any commune-level boundary adjustments occurred between 1790 and 1800 that would make a future polygon dated to 1800 differ from one dated to the creation year. Most French département boundaries stabilised quickly after 1790, but this should be checked once a source polygon is actually registered, rather than assumed.

### oq-gadm-global-adm1-not-registered

**No registered polygon source exists for any French département, including this one**

The polygon_route new_source_needed applies identically to every FRA subnational entry created so far (FRA-14, FRA-18, FRA-21, FRA-25, FRA-28, and now this one): GADM 4.1's global ADM1 release has the right schema and admin level but the locally present gadm-4.1-adm1 file is an 81-country subset that omits France. Until that global release (or an equivalent IGN historical département layer) is fetched and registered, none of these entries can move past polygon_status: unassigned. This is a repository-wide gap rather than something specific to Eure, and resolving it once would unblock all such entries plus any further French départements added later.

### oq-eure-fao1952-mitchell-coverage

**Extent of temporal coverage gaps in the juan-subnational source for this unit**

The routing evidence for unit FRA-FRD21 was not accompanied by a stated observed-vs-back-cast coverage percentage in the decision text handed to this page, unlike sibling entries (e.g. FRA-28 at 97.6% observed). Whether Eure's underlying juan-subnational series is similarly high-coverage, and which years if any are back-cast rather than directly reported, has not been checked against the source file and would matter for anyone treating this entry's series as a continuous observed record.
