# Santa Cruz de Tenerife (province of Spain)

## Summary

This entry covers the Spanish province of Santa Cruz de Tenerife from its creation in 1927 to the present. It is `type: subnational` because Spain has held continuous national sovereignty over these islands throughout; the polity row exists to carry the province as a reporting/administrative unit distinct from the national ESP chain, matching how the seven other Spanish provinces already in this database (Asturias, Cantabria, Cordoba, Lugo, Madrid, Ourense, Pontevedra, all spanning 1833-2025) are represented. Santa Cruz de Tenerife comprises the four western Canary Islands -- Tenerife, La Palma, La Gomera and El Hierro -- and was formed when the single Canary Islands province (in place since the 1833 Javier de Burgos provincial reform) was split in two, the eastern half becoming Las Palmas. Because the province did not exist under this name and these boundaries before 1927, its start_year departs from the country convention's default 1833 anchor, per the explicit-departure rule for provinces created by later splits (the same rule already applied to any other post-1833 Spanish province in this pipeline).

**Why this entry exists.** Input data: the routing decision for unit ESP-ES709 (admin_name "ES709", INE province Santa Cruz de Tenerife) established that this unit's data begins in 1865 -- 62 years before the 1927 split that created the province as such -- and continues to the present under mapspain-ign's cpro 38. The verdict's `proposed` field could only create the post-1927 polity (this entry); it explicitly could not resolve the 1865-1926 rows. What the data was previously matched to, and why that was wrong: absent this entry, all Santa Cruz de Tenerife-labeled rows across the whole 1865-2025 span would fall through to the national ESP row, which is roughly the entire Iberian peninsula plus archipelagos -- many multiples of this ~3,381 km2 territory. That is the generic-national-catchall failure this pipeline exists to fix province by province. What confirms this entity was distinct: the 1927 decree splitting the Canary Islands into two provinces is Spain's own administrative record (INE still carries cpro 35 vs 38 as the live distinction between Las Palmas and Santa Cruz de Tenerife), and it is exactly the same class of split-driven provincial creation this pipeline has already handled for other ESP provinces under the country convention's "explicit departure" rule. The pre-1927 unified Canary Islands province is a second, still-missing entity that this entry's existence makes visible but does not itself create.

## Sourced claims

- The Canary Islands' single province, established in 1833 under the Javier de Burgos reform, was split by decree in 1927 into two provinces: Las Palmas (eastern islands: Gran Canaria, Lanzarote, Fuerteventura) and Santa Cruz de Tenerife (western islands: Tenerife, La Palma, La Gomera, El Hierro).
- INE (Instituto Nacional de Estadistica) assigns Santa Cruz de Tenerife the province code (cpro) 38, distinct from Las Palmas (cpro 35); mapspain-ign, the source already used for 7 sibling ESP provinces in this database, keys its features by this cpro code.

## Decisions

### d-code-avoids-tf-collision

**Chose ESP-SCT-1927-2025 over ESP-TF-1927-2025 because TF was already taken**

The natural 2-letter code for Santa Cruz de Tenerife would follow the dominant <ISO3>-<SUBUNIT>-<start>-<end> pattern with SUBUNIT=TF (the common vehicle-plate/postal abbreviation for the province). That code, ESP-TF-1927-2025, was already assigned in this pipeline run to a different unit (ES702), so it is unavailable. SCT (initials of Santa Cruz de Tenerife) is used instead as the least ambiguous free alternative that still signals the province by its own name rather than an arbitrary token. Nothing else about the proposed routing, span, or container changes from this substitution.

### d-start-1927-departure

**start_year 1927 departs from the country convention's default 1833 anchor**

Most Spanish provinces in this database span 1833-2025, matching the 1833 Javier de Burgos provincial reform. Santa Cruz de Tenerife did not exist as a distinct province until the 1927 split of the single Canary Islands province, so this entry starts at 1927 per the country convention's explicit-departure rule for provinces created later than 1833. Data for this territory going back to 1865, while it was still part of the unified Canary Islands province, is deliberately left unassigned by this entry -- see the open question below -- rather than forced into this entry's span, since doing so would make the code years disagree with the frontmatter years.

## Open questions

### oq-pre1927-canary-islands-polity-missing

**1865-1926 Santa Cruz de Tenerife data has no home yet**

62 years of data (1865-1926) for this territory predate the 1927 province split and belong to the single, unified Canary Islands province (est. 1833), which is not yet a polity row in this database and has no boundary candidate registered here. A separate create_new proposal for 'Canary Islands (province of Spain), 1833-1927' is needed -- as a distinct polity encompassing both this province and Las Palmas -- likely triggered when the sibling unit ES708 (Las Palmas) is processed, since it should share the same pre-1927 predecessor rather than each creating a duplicate. Until that entry exists, this page's predecessor field is left empty even though a real predecessor territory existed.

### oq-las-palmas-sibling-status-unknown

**Whether ESP-ES708 (Las Palmas) has already been routed or proposed is unconfirmed**

The routing decision for this unit flagged, but did not resolve, whether the sibling province Las Palmas (ES708) has already been given its own post-1927 polity row. If it has not, both provinces' 1865-1926 data will independently surface the same pre-1927 gap, and whoever creates the pre-1927 Canary Islands polity should link it as predecessor to both ESP-SCT-1927-2025 and whatever code Las Palmas receives. If Las Palmas has already been created under a different code convention, that would also argue for renaming this entry for consistency before it accumulates dependents.

### oq-mapspain-ign-local-presence-unverified

**sources.yaml says mapspain-ign is not present locally, contradicting 7 existing builds**

The routing decision for this unit noted that sources.yaml marks mapspain-ign as not present locally, yet 7 sibling ESP provinces are already built from it in this database. This entry inherits the same registered-source route (cpro 38) and the same unresolved discrepancy: either sources.yaml is stale and should be corrected, or those 7 existing builds used a since-removed local copy and the actual feature fetch for cpro 38 may fail when attempted. This should be checked against the real file before assuming polygon assignment will succeed uneventfully.
