# Orne (département)

## Summary

Orne is a French département in Normandy (INSEE code 61), named for the Orne river, with its préfecture at Alençon. It was created in March 1790 during the Revolutionary reorganisation of France, assembled mainly from parts of the former province of Normandy (Perche and Alençonnais areas). Unlike Alsace-Lorraine, Territoire de Belfort, Corsica, or the overseas départements, Orne is not one of the four departures the harness's country convention lists from the default "1790 origin, still current" rule, so it takes the default: created 1790, in existence continuously to the present. This entry sets its start at 1800 rather than 1790 because no polity row in the current table represents metropolitan France for the 1790-1800 decade (the earliest France row is FRA-1800-1871); until such a row exists, containment cannot be tiled back to 1790, so the entry starts where a container is actually available and the decade gap is recorded as an open question rather than silently claimed. As a standard, uninterrupted département, Orne has never been contested territory, never changed hands, and has no distinct historical identity as a state; its type is subnational because it is, and has only ever been, an administrative subdivision of France, never a sovereign or quasi-sovereign entity in its own right.

**Why this entry exists.** This entry captures FAO/statistical-yearbook style data reported under the unit id FRA-FRD13 (admin_name "FRD13", the Eurostat/NUTS3 code for Orne), spanning 1862-2023, all of it currently matched or proposed to be matched here. That data was previously being absorbed into national FRA totals (FRA-1800-1871 / FRA-1871-1919 / FRA-1919-2025), which are roughly 550 times Orne's territory (France ~551,700 km2 vs Orne ~5,977 km2) and mix in every other département's production and population figures. Federico-Tena and INSEE both treat French départements, including Orne, as distinct sub-national reporting units with their own historical statistical series (population censuses, agricultural production) going back to the Revolutionary reorganisation, which is the historical confirmation that this is a real, separately-tabulated administrative entity and not an artefact of the data pipeline.

## Territorial extent

**Polygon status:** Not yet assigned. No polygon available in the GeoPackage for this period. `polygon_source: none`, `polygon_status: unassigned`. The registered sources checked do not cover this: `cshapes-europe` and `cshapes-2.0` represent all of France as a single national polygon per period (no département breakdown), and the locally-present `gadm-4.1-adm1` file is an 81-country subset that excludes France entirely, so no union/difference of currently-registered features can produce Orne's boundary. A département-level source (the full global GADM 4.1 adm1 release, or IGN ADMIN-EXPRESS) would need to be fetched before a polygon can be attached; that fetch is out of scope for this entry.

**Territory description:** Orne is a département in Basse-Normandie/Normandie in northwestern France, bordered by Calvados, Eure-et-Loir, Manche, Mayenne, and Sarthe. Its préfecture is Alençon; other principal towns include Argentan and Flers. Modern Orne covers approximately **5,977 km2** (INSEE figure for the current département), a boundary essentially unchanged since the 1790 creation aside from minor 19th-century commune-level adjustments common to all French départements. Because départements have kept their 1790 outlines with only such minor adjustments, a present-day départemental boundary (once obtained) would be a reasonable, low-risk stand-in for the full 1800-2025 span — a stated approximation, not an exact period source, and one that cannot be attached until the boundary data itself is fetched.

## Predecessors and successors

No predecessor: Orne has existed continuously as a French département since its 1790 creation, with no antecedent polity row representing the pre-département Ancien Régime provinces (Perche, parts of Normandy and Maine) that were merged to form it. No successor: Orne remains a current, ongoing administrative unit of France as of 2025, so `end_year` is set to 2025 (the harness's open-present convention) rather than to any dissolution date, because none exists.

## Decisions

### d-start-year-1800-not-1790

**Start year set to 1800, not the proposed 1790, to keep containment tiled**

The harness's proposed span_basis argues for start_year=1790, the year Orne was created as one of the original Revolutionary départements. However, the polity table's earliest row representing metropolitan France is FRA-1800-1871 (1800-1871) — there is no FRA row covering 1790-1800. Because the container edges must tile the whole span with no gap, and a container falling outside its own party's span is rejected by the containment gate, this entry cannot honestly claim containment back to 1790 without a container to attach to. Rather than leave a silent 10-year gap or attach an out-of-range container edge, this entry starts at 1800 (the code is FRA-61-1800-2025, and start_year=1800 in the frontmatter matches, satisfying the code/frontmatter year-equality gate). The missing 1790-1800 decade for Orne (and for France generally, at this granularity) is recorded as an open question rather than fabricated coverage.

### d-subunit-code-insee-61

**Used INSEE numeric code 61 as the subunit segment, matching existing FRA-NN sibling pages**

The dominant subnational pattern is <ISO3>-<SUBUNIT>-<start>-<end>, and country convention for FRA (evidenced by already-created sibling pages fra-14, fra-18, fra-21, fra-25, fra-28, fra-36 in this same working tree) uses the official INSEE numeric département code as the SUBUNIT segment rather than a letter abbreviation (unlike the ESP pages, which use 2-letter province abbreviations). Orne's INSEE code is 61, giving FRA-61-1800-2025, consistent with the precedent this country's own prior entries have already set rather than inventing a separate lettering scheme for France.

## Open questions

### oq-1790-1800-gap-uncontainered

**Orne 1790-1800 is uncontainered because no FRA row exists for that decade**

Orne was legally created in 1790, but this entry starts at 1800 solely because the polity table has no France-representing row covering 1790-1800 (the earliest is FRA-1800-1871). If a future entry adds a FRA-1790-1800 (or similarly-spanned) national row, this entry's start_year should be reconsidered and potentially extended back to 1790 with a matching container edge added, rather than leaving the decade permanently uncovered for every French département entry created under this same constraint.

### oq-no-polygon-source-fetched

**No département-level boundary source is currently registered or fetched**

This entry has polygon_status: unassigned because none of the registered sources (cshapes-europe, cshapes-2.0, gadm-4.1-adm1) currently provide French département-level geometry — cshapes carries France as one national polygon, and the locally-present GADM 4.1 adm1 file is an 81-country subset excluding France. Whether the full global GADM 4.1 adm1 release should be fetched, or an IGN ADMIN-EXPRESS source registered instead, is unresolved; either would need to be added to scripts/sources.yaml before this or any other French département entry (fra-14, fra-18, etc.) can get an assigned polygon.

### oq-data-span-vs-entry-span

**Whether the underlying FRA-FRD13 data (1862-2023) implies a narrower practical span than the 1800-2025 entry**

The routing decision's data span for this unit is 1862-2023, well inside the proposed 1790-2025 (now 1800-2025) administrative span. It is unresolved whether all years 1800-1862 and 2023-2025 should be treated as unobserved-but-valid (the département existed, simply wasn't in this data source) versus whether a different, tighter start/end should be used for a purely data-driven entry rather than the administrative-existence span; this entry follows the administrative-existence convention used elsewhere in the table (e.g. sibling FRA-NN pages), but the convention itself is not verified against a written policy.
