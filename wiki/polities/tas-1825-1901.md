# Van Diemen's Land (Tasmania) (to 1900)

## Summary

> **`polygon_status` migrated missing -> unassigned (2026-07-29).** `missing` is a legacy value that predates the documented vocabulary in [wiki/README.md](../README.md#page-schema), which says not to use it in new pages. It was never migrated, so the manifest's `claims_polygon_status` set omitted it and consumers were told this row does not claim a polygon. This row has no geometry at all, which is exactly what `unassigned` means. See [lint-polygon-status-vocabulary](../log.md#lint-polygon-status-vocabulary).


The British colony of Van Diemen's Land (renamed Tasmania on 1 January 1856) from its separation from New South Wales on 3 December 1825 to the eve of Australian federation. The island had been under NSW jurisdiction since the first British settlement at Risdon Cove in 1803; Governor Darling's 1825 proclamation made it a distinct colony. The WHEP row ends on 31 December 1900 before the 1 January 1901 federation.

- [log dangling-refs-audit-2026-04-15](../log.md#dangling-refs-audit-2026-04-15) — page created to resolve the TAS-1825-1901 dangling reference. CSV `notes` field already recorded the start-year correction (1800→1825).

### d-end-year-1901-not-1900

**The colony existed through all of 1900, so its exclusive `end_year` is 1901**

The Commonwealth of Australia was proclaimed on 1 January 1901, so this colony existed for every day of 1900 and ceased on the last of it. With `end_year` exclusive that is 1901, and the row previously said 1900 -- covering only to the end of 1899 and leaving 1900 with no colony at all.

The error was visible inside this table before it was visible in the data: the aggregate row [AUS-1800-1901](aus-1800-1901.md) already ends in 1901 and the successor states all begin in 1901, so the six colonies were the only rows dating federation to 1900. What surfaced it was the panel -- six Australian units report 1900 and those rows resolved to nothing, because the colony alias stopped at 1899 and the state alias began at 1901. Corrected 2026-09-17.

### d-canonical-name-tasmania-not-van-diemens-land

**The row is named "Tasmania (to 1900)", with Van Diemen's Land recorded in the prose**

The colony was Van Diemen's Land from 1825 and renamed Tasmania on 1 January 1856, so both names are correct for parts of this span and the page keeps both. The frontmatter carries `Tasmania`, for a mechanical reason that cost 195 layer-B rows.

The layer-B matcher resolves a label to a *family* of polity rows by normalised name, and `matchlib.norm()` strips parentheticals. Its five sibling colonies are named `<Colony> (to 1900)`, which normalises to the same string as their post-federation state rows -- `Victoria (to 1900)` and `Victoria (state of Australia)` both reduce to `victoria` -- so a row labelled "Victoria" in 1854 finds the colony. This row was `Van Diemen's Land (Tasmania) (to 1900)`, which reduces to `van diemen s land`: the label "Tasmania" resolved only to [AUS-TAS-1901-2025](aus-tas-1901-2025.md), whose span begins in 1901, and all 195 `sa_colonial` rows for 1854-1898 came back `year_uncovered`.

The defect was invisible because `state/territory_basis.csv` still credited this row with 195 rows from a `matched_rows.parquet` generated before a re-span -- exactly the staleness that file's orphan-code guard exists to catch. Regenerating stage 01 on 2026-09-17 surfaced it.
