# Vienne (department)

## Summary

Vienne is one of metropolitan France's original departements, created in 1790 out of parts of the former province of Poitou during the Revolutionary administrative reform that replaced the old provinces with a uniform grid of departments. It sits in west-central France, in the historic region of Poitou-Charentes (now folded into Nouvelle-Aquitaine), with Poitiers as its prefecture. This entry is type: subnational because Vienne has never been a sovereign polity or a distinct international reporting territory the way the national FRA chain represents France as a whole; it is a department-level administrative and statistical reporting unit, created here specifically to receive Vienne-labelled data (NUTS code FRI34) that would otherwise default-route to the national France row it is roughly 1/80th the size of. The entry spans 1800-2025 rather than the department's actual 1790 founding, only because the earliest FRA national row available in the table to container against (FRA-1800-1871/FRA-1800-1919) itself starts no earlier than 1800. Across the span covered, the department has, per the country convention's default rule, kept its present boundaries: it is not one of the four documented FRA departure cases (Belfort, the Alsace-Lorraine trio, Corse's 1975 split, or the overseas departments), all of which needed bespoke treatment rather than the default start/continuity assumption applied here.

Why this entry exists. Input data: a France NUTS unit labelled FRI34 (INSEE department code 86, Vienne), reporting at department granularity with 97.6% observed/blank-method values -- the routing decision flagged this high non-imputed share as evidence of genuine subnational statistical reporting rather than a reconstructed or interpolated series, which is what justifies giving it its own polity row instead of leaving it folded into the national total. Previously matched to: by default, any unrouted French department-level series falls to the national FRA chain, which is wrong here because those rows represent all of metropolitan France -- roughly 550,000 km2 versus Vienne's ~6,990 km2, an overstatement of territory by a factor of about 80. Confirmation of distinctness: Vienne is one of the departements created by the National Constituent Assembly's 1790 reform, a legal and administrative act that has defined it as a discrete unit of French sub-national governance for over two centuries, with its own NUTS3/INSEE code (FRI34/86) used by Eurostat and INSEE precisely because department-level statistics are collected and published as such, independent of the national series.

Territory description: Vienne department, in west-central France, roughly bounded by Deux-Sevres and Charente to the west/southwest, Indre-et-Loire and Indre to the north/northeast, Haute-Vienne to the southeast, and Charente-Maritime to the south. Modern Vienne covers approximately 6,990 km2 -- this is a reference figure taken from current French administrative statistics for the department as it exists today, not a measurement of any polygon attached to this entry, since none is attached yet. A reader can locate it on a modern map as the department directly south of the Loire valley around Chatellerault, straddling the A10 motorway between Tours and Bordeaux.

## Sourced claims

- Vienne was created in 1790 as one of the original approximately 83 departements of the French Revolutionary administrative reform, replacing the pre-1789 province structure (Vienne corresponds to the eastern part of the former province of Poitou); this is standard French administrative history reflected in INSEE's own department-code registry (code 86).
- The France NUTS3 code FRI34 corresponds to INSEE department 86 (Vienne), and Eurostat's NUTS classification publishes department-level statistics under this code independently of the national FRA aggregate -- concrete evidence that Vienne-labelled data is a distinct reporting geography, not a subdivision convenience invented for this table.

## Decisions

### d-code-fra-vne-not-fra-vie

**Subunit code chosen as VNE, not VIE or the numeric 86**

Two prior draft pages for this exact unit already exist on disk as untracked files: wiki/polities/fra-vie-1800-2025.md (code FRA-VIE-1800-2025) and wiki/polities/fra-86-1800-2025.md (code FRA-86-1800-2025), both describing the same France NUTS3/INSEE-86 department, Vienne. Neither row appears in the built polities_database.csv, so both are orphaned drafts rather than entries this pipeline has already committed to the table. The harness's rejection message asserted FRA-VIE-1800-2025 names 'a different territory' from unit FRI34, which does not match what that file's own content says (it is Vienne, FRI34, verbatim); FRA-86-1800-2025 is likewise Vienne under the numeric INSEE code. Rather than take a third guess at a code that might collide with a ledger entry this agent cannot see, VNE (an unambiguous three-letter mnemonic not used anywhere in the current wiki/polities directory or the CSV) is used here. Content otherwise follows the same reasoning as the two prior drafts, since that reasoning was sound; only the code changed, per the instruction to change nothing else.

### d-start-year-1800-not-1790

**start_year set to 1800, not the routing decision's proposed 1790**

The routing decision proposes start_year=1790, citing Vienne's creation among the ~83 original Revolutionary departments. The polities table has no FRA national row earlier than FRA-1800-1871/FRA-1800-1919 (verified by grepping '^FRA' in polities_database.csv: only FRA-1800-1871, FRA-1800-1919, FRA-1871-1919, FRA-1919-2025 exist). The containment gate rejects an edge whose interval falls outside either party's own span, so no container edge can start before 1800. Rather than leave 1790-1800 uncontainered or falsely containered, this entry's start_year is pulled in to 1800, matching both the code and the frontmatter (as the containment gate also checks that the code years equal the frontmatter years). The missing decade is recorded as an open question rather than papered over.

### d-single-aggregate-container-row

**Container uses aggregate FRA-1800-1919, not the split FRA-1800-1871/FRA-1871-1919 pair**

FRA-1800-1871 ('with Alsace-Lorraine, to 1871') and FRA-1871-1919 ('without Alsace-Lorraine, 1871-1919') tile 1800-1919 by Alsace-Lorraine status; FRA-1800-1919 ('France, to 1919') is a third row spanning the same years as a single aggregate. Vienne, in Poitou-Charentes, is untouched by the Alsace-Lorraine cession either way, so using the aggregate avoids introducing an internal 1871 seam that has no bearing on this department's own history, and avoids the redundancy of two edges where one suffices.

## Open questions

### oq-duplicate-draft-pages-for-same-unit

**Two other untracked draft pages already describe this exact territory under different codes**

wiki/polities/fra-vie-1800-2025.md (FRA-VIE-1800-2025) and wiki/polities/fra-86-1800-2025.md (FRA-86-1800-2025) are both, on inspection, pages for the same unit this entry covers: France NUTS3 FRI34 / INSEE department 86, Vienne. All three files are currently untracked and none appears in the built polities_database.csv, so it is unclear which (if any) the harness intends to keep. Before this batch is committed, someone needs to reconcile the three FRA Vienne drafts down to one code and delete the other two files, or the next table build will either silently pick one arbitrarily or fail on a duplicate-territory check. This entry (FRA-VNE-1800-2025) should not be treated as the final answer to that reconciliation, only as a third data point that the same routing decision keeps producing pages under different codes.

### oq-1790-1800-uncontainered-gap

**1790-1800 is real Vienne history with no FRA polity row to container against**

Vienne was created as a department in 1790, ten years before the earliest FRA national row in the table (FRA-1800-1871/FRA-1800-1919). Because a container edge cannot fall outside the container's own span, this entry's start_year was set to 1800 rather than 1790, leaving the 1790-1800 decade unrepresented. If a FRA national row covering pre-1800 Revolutionary/Consulate France is ever added, this entry's start_year and container list should be revisited together, since extending one without the other would fail the containment tiling check again.

### oq-gadm-france-not-on-disk

**gadm-4.1-adm1 is registered but the on-disk copy excludes France**

polygon_source is set to the registered slug gadm-4.1-adm1 with polygon_status unassigned and no polygon_feature_id, because the routing decision found the on-disk GADM admin-1 extract is an 81-country curated subset that does not include FRA. Fetching the global GADM 4.1 admin-1 package (or a France-inclusive re-fetch) is a prerequisite before this or any other FRA department can move from unassigned to assigned. Until then the ~6,990 km2 figure in territorial extent is a modern reference figure, not a polygon measurement, since no geometry is attached.

### oq-boundary-stability-unverified

**Vienne's boundary continuity since 1790 was assumed from the country convention, not independently checked**

The routing decision applied the FRA country convention's default rule (original department, not one of the four documented departure cases, so treated as boundary-stable since creation) without checking Vienne specifically for 19th- or 20th-century commune or arrondissement boundary revisions of the kind that occasionally reshape French departments at the margins. This entry assumes continuity has held for area purposes; if a source is later found describing a boundary change to Vienne, the single 1800-2025 span here would need to be split at that year.
