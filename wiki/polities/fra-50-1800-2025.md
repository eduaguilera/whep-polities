# Manche

## Summary

Manche is a French département occupying the Cotentin peninsula in Normandy, on the English Channel coast, containing Cherbourg and the city of Saint-Lô. It is coded `subnational` because it is an administrative subdivision of a sovereign state, not a distinct sovereignty claim: France's sovereignty over this territory is continuous and undisputed across the whole 1800-2025 span, and that claim is already carried by the three national FRA rows in this table (FRA-1800-1871, FRA-1871-1919, FRA-1919-2025). This entry exists solely to give a home to sub-national statistics reported at the département level -- data keyed to Manche or its NUTS3 code FRD12 -- which cannot correctly be attributed to a national French row roughly a hundred times its area without conflating département-level figures with all-France totals. Manche is one of the original ~83 départements created by the 1790 Revolutionary administrative reform and is not among the four départements this country's routing convention explicitly departs from (Belfort's 1922 re-formation, the two Alsace-Lorraine départements' repeated border changes, and the 1975 Corsican split), so it follows the default span rule, adjusted to open in 1800 to match the earliest available FRA container row rather than its true 1790 creation date.

**Why this entry exists.** This entry captures juan-subnational source data reported for unit FRA-FRD12 (Manche, Eurostat NUTS3 code FRD12, INSEE department code 50). Before this decision, that data had no French row to route to other than the three national FRA chain entries (FRA-1800-1871, FRA-1871-1919, FRA-1919-2025), each of which represents the whole country and is roughly a hundred times Manche's own area -- routing département-level statistics there would have silently merged them into all-France totals. What confirms Manche as a distinct, separately-tabulated entity rather than an arbitrary subdivision invented for this pipeline is that it is one of the original départements created by the 1790 Revolutionary administrative reform, has been continuously enumerated under INSEE code 50 in French national statistics ever since, and independently carries Eurostat NUTS3 code FRD12 in EU regional statistics -- the same dual national/EU statistical apparatus already used to justify sibling entries such as FRA-18 (Cher), FRA-28 (Eure-et-Loir), and FRA-91 (Essonne).

## Territorial extent

**Polygon status:** Not yet assigned. No polygon available in the GeoPackage for this period. The routing decision that created this entry names a specific candidate -- GADM 4.1 admin-1 feature FRA.28_1 -- but the GADM 4.1 admin-1 file currently installed in this repository is an 81-country subset that does not include France (confirmed by a 0-row query), so that feature cannot actually be resolved from any file on disk. Assigning it would require first fetching and registering the full global GADM 4.1 release in scripts/sources.yaml, which has not been done. This matches the status of every other French département sibling entry already in this table (fra-18, fra-21, fra-25, fra-28, fra-36, fra-37, fra-39, fra-41, fra-58, fra-70, fra-71, fra-77, fra-89, fra-14), none of which carry a polygon yet for the same reason.

**Territory description:** Manche is the northwesternmost département of Normandy, occupying the Cotentin peninsula that projects into the English Channel between the Bay of the Seine and the Gulf of Saint-Malo. Its administrative seat is Saint-Lô, and it contains the port city and former naval base of Cherbourg at the peninsula's tip, as well as Mont-Saint-Michel on its southwestern border with Brittany. Modern Manche covers approximately 5,938 km2 (INSEE figure for the current département), a scale consistent with a single French département among roughly 96 metropolitan units. No independent measurement of this figure has been made from any polygon in this repository, since none is yet attached to this entry; the 5,938 km2 figure is the modern administrative area as published by INSEE, not a geometry measurement.

## Predecessors and successors

Manche has no predecessor or successor row: it is one of the original ~83 départements created directly by the 1790 Revolutionary administrative reform, not a unit formed by merging, splitting, or renaming any earlier or later French subdivision (unlike the four re-formed départements -- Belfort, the Alsace-Lorraine pair, and the Corsican split -- that this country's default start rule explicitly treats as departures). It has kept the same INSEE code (50) and essentially the same boundary since creation and remains an active, unaltered French département today, so both predecessor and successor lists are empty and end_year uses the open-end convention 2025.

## Decisions

### d-start-year-1800-not-1790

**start_year set to 1800, not the 1790 creation date, to match the earliest FRA container row**

The routing decision's span_basis proposes start_year 1790, the year Manche was created as one of the ~83 original Revolutionary départements. This entry instead uses 1800, following the convention already established by sibling département entries in this table (fra-18, fra-21, fra-25, fra-28, fra-36, fra-37, fra-39, fra-41, fra-58, fra-70, fra-71, fra-77, fra-89, fra-14), all of which open in 1800 rather than 1790. The reason is structural, not evidential: the earliest national FRA row in this database is FRA-1800-1871, so a container edge cannot validly start before 1800 -- the containment gate rejects an edge whose start falls outside the container's own span. Manche's actual administrative existence back to 1790 is real, but this table has no France row spanning 1790-1800 to attach to, so the entry is left starting where the container chain starts, exactly as every sibling département entry already does. If a pre-1800 French national row is ever added, this entry's start_year and its first container edge should move to 1790 to match.

### d-polity-code-insee-not-nuts3

**Polity code uses the INSEE numeric département code (50), not the NUTS3 code FRD12 cited in the routing decision**

The routing decision names the input unit as FRA-FRD12 (Eurostat NUTS3 code FRD12), but this entry's code is FRA-50-1800-2025, using INSEE department code 50 -- the code long used in French national statistics and matching the numbering scheme of every sibling département entry already in this table (fra-28 = Eure-et-Loir INSEE 28, fra-91 = Essonne INSEE 91, fra-14 = Calvados INSEE 14, etc.). NUTS3 FRD12 and INSEE 50 refer to the same territory (Manche); INSEE numbering was chosen for consistency with the established sibling pattern rather than introducing a second numbering convention into this set of pages.

### d-polygon-unassigned-not-new-source

**polygon_status left unassigned rather than pulling the GADM 4.1 feature id (FRA.28_1) the routing decision names**

The routing decision's polygon_detail names a candidate feature id, FRA.28_1, from the full global GADM 4.1 admin-1 release, and flags the route as new_source_needed because the GADM file currently on disk in this repository is an 81-country subset that excludes France. Since that global release has not actually been fetched and registered in scripts/sources.yaml as of this page, no working polygon route exists yet to attach, and claiming polygon_status: assigned or proxy against a feature id that cannot currently be resolved from any file in this repository would misrepresent the state of the data. This matches every sibling département entry in the table (fra-18 through fra-91), all of which carry polygon_source: none / polygon_status: unassigned for the identical reason. Note that GADM's GID_1 index 28 (FRA.28_1) is unrelated to INSEE department code 28 (Eure-et-Loir) used in this entry's own code choice above -- the two are independent numbering schemes that happen to share a digit.

## Open questions

### oq-gadm-global-fetch-pending

**Manche has no attached polygon because the global GADM 4.1 admin-1 release has not been fetched**

The routing decision identifies a specific candidate feature, FRA.28_1 in gadm-4.1-adm1, as Manche's boundary, but the copy of that source currently installed in this repository is an 81-country subset that does not include France at all (confirmed by a 0-row query against it). Until someone fetches and registers the full global GADM 4.1 admin-1 release in scripts/sources.yaml, this entry -- and every other French département sibling entry in this table -- must stay polygon_status: unassigned. When that source is added, the correct next step is to verify FRA.28_1 actually resolves to Manche (Basse-Normandie, Cotentin peninsula) rather than to a neighbouring département before assigning it, since GID_1 indices are assigned in an internal GADM ordering that has not been independently checked here.

### oq-vintage-risk-not-yet-stated-in-data

**A modern GADM boundary would be a low-risk but unverified proxy across the full 1800-2025 span**

The routing decision's polygon_detail flags a vintage_risk: Manche's départemental boundary has been stable since its 1790 creation, unlike the four re-formed French départements (Belfort, the two Alsace-Lorraine départements, and the Corsican split) explicitly excluded from the default span rule. This suggests a present-day administrative polygon should be a reasonable proxy for the whole 1800-2025 span once fetched, but that claim has not actually been checked against any historical atlas or boundary-change record for Manche specifically -- it is inferred from Manche not appearing on the exclusion list, not confirmed independently. Before assigning any polygon here, that stability claim should be verified rather than taken on the routing decision's word alone.

### oq-data-coverage-not-summarized

**The juan-subnational row count and year range for Manche have not been checked from this page**

The routing decision that created this entry does not state how many rows or which years of juan-subnational data are keyed to FRA-FRD12 / Manche, unlike the Eure-et-Loir sibling entry which cites a specific coverage figure (97.6% observed, non-back-cast). This page cannot state that number without querying the underlying data file directly, and it would be worth pinning it in a follow-up so downstream users of this row know how much of its span is measured versus imputed.
