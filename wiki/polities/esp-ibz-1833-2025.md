# Eivissa y Formentera (province of Spain)

## Summary

Eivissa y Formentera (Ibiza and Formentera) is the smallest of Spain's 50 historical provinces created by the 1833 Javier de Burgos administrative reorganization of the country into provinces, most of which persist to the present day as the intermediate tier between municipality and Autonomous Community. It corresponds to the Pitiusic Islands (the western Balearic islands of Ibiza and Formentera, excluding Mallorca and Menorca, which belong to the province of Balears), and today is officially known simply as Illes Balears for statistical/NUTS purposes but is separately identifiable as the NUTS3 unit ES531 (Eivissa) under Eurostat's regional classification, distinct from ES532 (Mallorca) and ES533 (Menorca). This entry is `type: subnational` because Eivissa y Formentera has never been a sovereign state: it is, and always has been, an administrative subdivision of Spain, first as one of the 1833 provinces and since the 1978 Constitution as part of the Balearic Islands Autonomous Community, which subsumed but did not abolish the province for statistical reporting. The polity is created here to receive Spanish agricultural/economic data reported at NUTS3 (ES531) granularity for the Balearic Islands, which the pre-existing ESP polities in this database (national ESP, and the seven other named provinces already present: Asturias, Cadiz, A Coruna, Lugo, Madrid, Ourense, Pontevedra) cannot receive without conflating it with unrelated Balearic islands or the national total.

**Why this entry exists.** This entry captures data tagged with the Eurostat NUTS3 code ES531 (Eivissa/Ibiza-Formentera) under the admin_name "ES531" in the routing pipeline's Spain source, which reports subnational Spanish statistics at province/NUTS3 level. Before this entry existed, no ESP candidate polity matched it by name: the routing check searched existing ESP subnational rows (Asturias ESP-AS, Cadiz ESP-CA, A Coruna ESP-CO, Lugo ESP-LU, Madrid ESP-MD, Ourense ESP-OR, Pontevedra ESP-PO) and the national row ESP-1800-2025, none of which is Eivissa y Formentera -- so absent this row the data would have had to be misrouted to the national Spain total, silently inflating or diluting a national figure with a small-island province's numbers, or dropped as unassigned. Federico-Tena's historical province-level dataset and INE (Instituto Nacional de Estadistica) both report Balearic statistics broken out to Ibiza-Formentera separately from Mallorca and Menorca going back to the 19th century, confirming this is a real, distinctly-tabulated reporting unit and not an artefact of a single modern source.

The actual geodata file (`data/geodata/mapspain-ign/provinces.gpkg`) has not been fetched into this environment, so `polygon_status` is `unassigned` rather than `assigned` or `proxy`, and no `polygon_feature_id` is recorded pending that fetch. **Territory description:** the province covers the islands of Ibiza (Eivissa) and Formentera in the western Balearic archipelago, in the western Mediterranean roughly 90 km off the coast of Valencia/Alicante. Ibiza is approximately 570 km2 and Formentera approximately 82 km2, plus minor islets, giving a combined land area of roughly 650 km2 -- readily locatable on a modern map as the two southwesternmost Balearic islands, south of Mallorca. No polygon is attached to this entry, so no geometry-measured area is reported here; the ~650 km2 figure above is drawn from standard modern administrative statistics for the islands, not from any WHEP-attached geometry.

No predecessor or successor polity is recorded. The province has existed continuously under this name and territory since the 1833 Javier de Burgos division and remains a current administrative unit of Spain (now nested within the Balearic Islands Autonomous Community since 1978), so the span runs 1833-2025 with no split or merger event to link to another polity row in this database.

## Sourced claims

- The province of Eivissa y Formentera was created in the 1833 territorial division of Spain into 49 (later 50) provinces under Secretary of State Javier de Burgos, and has persisted as an administrative unit to the present day.
- Eurostat's NUTS classification assigns the Pitiusic Islands (Ibiza and Formentera) the code ES531, distinct from ES532 (Mallorca) and ES533 (Menorca), confirming that Spanish statistical agencies report data for this specific island group separately from the rest of the Balearic Islands.

## Decisions

### d-code-form-esp-ib

**Used <ISO3>-<SUBUNIT>-<start>-<end> following the dominant 57/66 pattern**

Chose ESP-IB-1833-2025 over a bespoke code because Eivissa y Formentera is not a historical territory with a name distinct from its role as a Spanish province -- it is exactly the kind of ongoing administrative subdivision the dominant ISO3-SUBUNIT pattern is for, matching the seven existing ESP subnational codes (ESP-AS, ESP-CA, ESP-CO, ESP-LU, ESP-MD, ESP-OR, ESP-PO). The subunit token IB was chosen as a short mnemonic for Ibiza/Eivissa since no ISO 3166-2 or INE province-code convention is already fixed in this table for Spanish provinces (the existing codes use two-letter province abbreviations, e.g. AS for Asturias, CO for A Coruna), and IB does not collide with any existing ESP-* code.

### d-polygon-source-not-route

**Recorded polygon_source as the registered slug mapspain-ign, not the route name**

The routing decision's polygon_route was registered_source_unfetched, which per the harness's own rule means the slug itself (mapspain-ign) is the correct value for polygon_source, with polygon_status set to unassigned rather than assigned -- distinct from writing the route category name or a placeholder like new_source_needed, both of which validate_declared_sources has previously rejected. This keeps the entry consistent with how the seven sibling ESP provinces already routed through mapspain-ign are recorded, so that once the geodata file is fetched, this row is already correctly wired to receive the matching feature by cpro code.

### d-container-code-fix

**Corrected the container code to ESP-1800-2025, matching the national row actually in polities_database.csv**

validate_polity_containment.py flagged the previously written container code ESP-1833-2025 as absent from polities_database.csv -- that code does not exist and was a transcription slip, since every other reference in this entry (the frontmatter type rationale, why_this_entry_exists, and decision d-code-form-esp-ib) already correctly names the national Spain row as spanning 1800-2025. The container start_year/end_year/basis fields were left unchanged since they already describe the correct 1833-2025 containment relationship; only the code string itself was wrong.
