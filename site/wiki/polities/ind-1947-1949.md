# India (1947-1949)

## Territorial extent

This row covers post-partition India from independence, **15 August 1947**,
through **early January 1949**. Its polygon binding is CShapes-2.0
`gwcode=750`, `gwsyear=1947`
[cshapes-2.0 §coding-states](../sources/cshapes-2.0.md#coding-states). Reading
the underlying CShapes shapefile directly (`data/geodata/cshapes-2.0/CShapes-2.0.shp`)
shows `gwcode=750` has a single continuous polygon time-step running
`1947-08-15` → `1949-01-04` at area **3,046,196.8 km²**, followed immediately
by a new time-step `1949-01-05` → `2019-12-31` at **3,152,040.8 km²** — a jump
of **+105,844 km²**. Measuring the committed database polygon for this row
(`data/final/polities_database.gpkg`, reprojected to the equal-area CRS
ESRI:54034) gives **3,046,040 km²**, consistent with the raw shapefile figure
to within rounding/reprojection error; the CSV's `polygon_area_km2` field is
`null` and this measured figure is not written back into frontmatter per the
task instructions binding this ingest, but it resolves the open question
below.

For comparison, the predecessor row's polygon (IND-1937-1947, same gwcode,
`gwsyear=1937`) measures **4,227,266 km²**, and the successor row
(IND-1949-2025, `gwsyear=1949`) measures **3,151,797 km²** — matching the
post-1949-01-05 CShapes time-step. So the 1937→1947 drop
(~1.18M km², the partition of Pakistan) and the 1947→1949 gain
(~105,844 km²) are both real geometric changes in the underlying CShapes
data, not artefacts.

**What is the +105,844 km² gain on 1949-01-05?** CShapes does not annotate
individual time-step transitions with an event label, so this is inference,
not a direct citation, but the magnitude and date line up closely with the
UN-mediated **Kashmir ceasefire line**, which took effect 1 January 1949
(formalized in the Karachi Agreement of 27 July 1949): Indian-administered
Jammu & Kashmir (the Kashmir Valley, Jammu, and Ladakh, excluding
Pakistan-administered Azad Kashmir/Gilgit-Baltistan) is on the order of
100,000–105,000 km², matching the jump closely. This reading is directly
supported by CShapes' own stated coding rule for contested territory:
"Instead of coding disputed territories separately... we assign them to a
given state based on its de facto control over the region" — and Kashmir is
named explicitly as assigned to "the Line of Control"
[cshapes-2.0 §coding-borders](../sources/cshapes-2.0.md#coding-borders).
Biger similarly notes that the India–Pakistan boundary "in the Jammu and
Kashmir region... is still in dispute"
[biger-1995 §india](../sources/biger-1995.md#india), consistent with CShapes
treating it as a de facto rather than a treaty boundary.

Because this 1949-01-05 change falls essentially at the row boundary already
drawn between IND-1947-1949 and IND-1949-2025 (both dated to calendar year
1949), the existing two-row split already captures it — **no further split
of IND-1947-1949 is warranted for the Kashmir ceasefire-line change**.

**State-system continuity.** Reading the raw COW state-system-membership
data directly (`wiki/sources/data/cow-v2024/statelist2024.csv`, ccode=750,
IND): India's COW tenure runs `1947-08-15 → 2024-12-31` as a single
uninterrupted row — no gap or re-entry recorded anywhere near 1949. This
COW record is about *state-system membership*, not territory, and per WHEP's
polity-definition rule it cannot by itself justify or preclude a split; it
is reported here only as a countercheck that no external dataset in this
project's sources treats early 1949 as a legal-continuity break for India,
which is consistent with treating IND-1947-1949 → IND-1949-2025 purely as a
territorial split rather than a regime-change split.

**Hyderabad annexation — a change the CShapes polygon does *not* register.**
Operation Polo (17–18 September 1948) brought Hyderabad State into the
Indian Union, with the Nizam's Instrument of Accession signed 23 November
1948 — both dates fall inside this row's own 1947–1949 span. However, the
raw CShapes shapefile shows **no area change** for `gwcode=750` at any point
between 1947-08-15 and 1949-01-04: the single time-step spans straight
through the annexation with a constant 3,046,196.8 km². The most defensible
reading is that CShapes' polygon for India already included princely-state
territory such as Hyderabad throughout the colonial and early-independence
period (princely states were never separately-coded independent GW/COW
units — they sat under British paramountcy, not the "dependency" category
CShapes tracks for colonies/protectorates/mandates
[cshapes-2.0 §coding-dependencies](../sources/cshapes-2.0.md#coding-dependencies)).
Under the WHEP polity-definition rule (a new row is created for *territorial*
change, not *legal/administrative* status change), Hyderabad's annexation
is exactly the kind of event that does **not** by itself justify splitting
IND-1947-1949 — the land was already inside India's mapped extent.

That said, this exposes a genuine **overlap concern, not resolved here**: the
wiki also carries a separate `HYD-1724-1948` row for Hyderabad State whose
`successor` field points to `IND-1947-1949`, but this page's own
`predecessor` frontmatter lists only `IND-1937-1947` — Hyderabad is not
listed as a predecessor here, and if CShapes' India polygon already includes
Hyderabad's territory for the full 1937-1949 window, then IND-1937-1947 and
IND-1947-1949 may already double-count Hyderabad's ~211,298 km² against the
separately-tracked HYD row for the overlapping years. This is flagged as an
open question below rather than resolved, since resolving it would mean
editing frontmatter/CSV rows outside this task's scope.

Partition-year ambiguity for 1947-dated production/trade rows: ~15–20%
possible overstatement accepted (decision dec-ind-1947-partition-year,
unchanged by this ingest). Flag "README known polygon/data extent mismatch"
remains closed — documentation gap only, same closure as IND-1937-1947.

## Sugar data diagnosis

Reported aggregate sugar=1,589,393,500 tonnes (n4) is a pipeline display artefact in territorial_flagged.json, NOT a production data error.

Root cause: the staples() function in pipelines/polity-autoimprove/02_territorial_evidence.py matches all items containing "sugar" and all units containing "tonne", then computes a single median across the mixed series without separating by unit first. The 4 matched rows for IND-1947-1949 are: mitchell sugar cane 3,176,000 t (1948) and 3,221,000 t (1949) in actual tonnes; fao1952 centrifugal/non-centrifugal cane sugar 1,255 and 2,787 in "1000 tonnes". Sorted: [1255, 2787, 3176000, 3221000]. Median = (2787+3176000)/2 = 1,589,393.5. The unit mode() returns "1000 tonnes" (alphabetically precedes "tonnes" in a 2-2 tie), so the scaling logic multiplies by 1000 yielding 1,589,393,500.

The underlying source values are correct: Mitchell sugar cane ~3.2 Mt/yr (plausible); FAO 1952 centrifugal 1,255,000 t + non-centrifugal 2,787,000 t = 4,042,000 t total (consistent with late-1940s India). No correction to before_1961.csv or any production dataset is required.

The earlier wiki note "Sugar unit-label display bug in pipeline noted and fixed in code" was premature — the scaling logic existed but the cross-unit mixing was not corrected.
