# Portalegre (NUTS region of Portugal)

## Summary

Portalegre is a NUTS III statistical/administrative district in inland eastern Portugal (Alto Alentejo), bordering Spain (Extremadura and Badajoz province) to the east, part of the Alentejo NUTS II region. It corresponds closely to the pre-existing Portalegre distrito, one of Portugal's 18 mainland districts, centred on the city of Portalegre. This entry is `type: subnational` because it is a sub-national statistical reporting unit created by the NUTS classification introduced around Portugal's 1986 EU accession, not a sovereign polity: Portugal held sovereignty over this territory throughout, and this row exists only to carry data reported at the district/NUTS III level rather than the national level. The span 1986-2025 follows the country convention's default rule for Portuguese NUTS regions established in this batch of sibling creations (PT11, PT15, PT16, PT18, PTAV, PTBJ, PTEV, PTGU, PTLE): no departure trigger (post-2015 metropolitan restructuring, or pre-NUTS historic-district reporting) applies to Portalegre, so it gets the plain 1986 start used for the rest of the batch.

**Why this entry exists.** The routing decision this page implements concerns source unit PRT-PTPG (admin_name PT_PG, country Portugal) with 144 candidate data years, of which 76% (109 years) were left `unroutable` after two prior routing retries because no Portuguese sub-national polity existed in the table to receive them for the post-1986 NUTS period. Those years were previously left unmatched to any polity at all -- not wrongly matched to a different territory, but simply dropped, which the harness flagged as unacceptable because the source reports real values for a territory that did exist. The decision separately surfaces that a related sibling unit, PT_FA (Faro), was inconsistently matched to the national polity PRT-1800-2025 for its 1880-1988 span while every other Portuguese NUTS sibling (including Portalegre) was correctly left unroutable for the same pre-1986 period; that Faro match is identified as the actual error, not a precedent to repeat here. Historical confirmation that Portalegre is a distinct reporting/administrative unit rather than an artefact of a data label: it is one of mainland Portugal's 18 historic distritos, predating the 1986 NUTS framework, and NUTS III simply layered a Eurostat-standard statistical boundary onto an administrative division that already existed and was already used for district-level reporting.

District/NUTS III boundaries here have been essentially stable since long before 1986 (per the routing decision's own vintage-risk assessment, "Low"), so a single modern GADM adm1 feature, once fetched, should validly represent the whole 1986-2025 span without a period-specific vintage adjustment.

## Decisions

### d-code-follows-nuts-pattern

**Code follows the ISO3-SUBUNIT-start-end pattern used by sibling NUTS districts**

PRT-PG-1986-2025 follows the dominant 57-row pattern (<ISO3>-<SUBUNIT>-<start>-<end>), matching how the other Portuguese NUTS III siblings created in this same batch (PT11, PT15, PT16, PT18, PTAV, PTBJ, PTEV, PTGU, PTLE) are coded. Portalegre is not a historical territory with a name of its own in the sense that Alaska Territory or Hyderabad are -- it is a modern statistical-administrative unit layered on an existing distrito -- so the bespoke-code exception does not apply. Portugal has zero pre-existing subnational codes in the table, so this entry and its siblings jointly set the country's precedent; following the shared pattern keeps that precedent internally consistent rather than inventing a one-off naming scheme for the first Portuguese subnational rows.

## Open questions

### oq-pre1986-portalegre-data

**What carries Portalegre-labelled data recorded before 1986?**

The routing decision reports 144 total candidate data years for source unit PT_PG and states that 109 of them (76%, pre-1989) were marked unroutable rather than assigned anywhere. If any of those pre-1986 years reflect real reported values (as opposed to structurally absent data), they currently have no polity to attach to: PRT-PG-1986-2025 cannot claim them, since no NUTS III classification existed before 1986, and the decision explicitly identifies the alternative -- matching pre-1986 years to the national polity PRT-1800-2025, as was wrongly done for sibling PT_FA -- as the error being corrected here, not a model to repeat. Whether genuine pre-1986 Portalegre-labelled observations exist, and if so what pre-NUTS Portuguese administrative unit (the historic Portalegre distrito itself, potentially back-dated) should carry them, is unresolved and needs checking against the raw source table.

### oq-gadm-portugal-fetch

**GADM 4.1 adm1 has zero Portugal features in the local fetch**

polygon_source is set to gadm-4.1-adm1 with polygon_status unassigned because the routing decision states the locally fetched GADM 4.1 admin-1 file is restricted to an 81-country subset that excludes Portugal entirely (0 features), even though GADM publishes Portuguese distrito/NUTS III boundaries globally and the source is already registered with id_column=GID_1. Until a Portugal-inclusive fetch (either the global GADM 4.1 file or a Portugal-specific re-fetch) is obtained, no GID_1 feature_id can be assigned to this row and polygon_area_km2 stays unset. The routing decision separately flags low vintage risk (Portalegre's distrito boundaries predate 1986 and are essentially unchanged since), so once fetched a single feature should validly cover the whole 1986-2025 span without needing a period-specific vintage.

### oq-sibling-overlap-fa

**PRT-PTFA's inconsistent pre-1989 routing may recur in other already-created siblings**

The routing decision explicitly flags that PRT-PTFA (Faro) was matched to PRT-1800-2025 for 1880-1988 while every other Portuguese NUTS sibling, including this one, correctly left that span unroutable, and calls the Faro verdict the likely actual error rather than a pattern to follow. This page assumes that inconsistency does not extend to Portalegre's own pre-1986 span (tracked separately above), but it has not been independently verified whether any other sibling page created in this same batch (PT11, PT15, PT16, PT18, PTAV, PTBJ, PTEV, PTGU, PTLE) carries the same stray pre-1989 national-row match, which would mean overlapping territory claims across multiple sibling entries simultaneously and should be swept and corrected together.
