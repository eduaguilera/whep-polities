# Drôme (département)

## Summary

Drôme is one of the original French départements created in the Revolutionary territorial reorganisation, occupying the middle Rhône valley in south-eastern France (present-day region Auvergne-Rhône-Alpes), with its préfecture at Valence. This entry is `type: subnational` rather than national because sovereignty over the territory rests with France throughout its existence -- the point of the row is to carry a French sub-national reporting/administrative unit distinct from the country-level FRA chain, following the dominant pattern used for the other 56 non-bespoke subnational rows in this database (e.g. Spain's ESP-AS, ESP-CA). It spans 1800-2025 in this database (see the open question and decision on why not 1790) with no predecessor or successor, since the département has neither been created out of an earlier database polity nor dissolved or restructured since. It containers against the three successive France national rows (FRA-1800-1871, FRA-1871-1919, FRA-1919-2025), which together tile its whole span with no gap.

**Why this entry exists.** Input data: the routing decision names unit `FRA-FRK23` / admin_name "FRK23", country France, with no row count or specific dataset supplied in the decision payload itself -- the reasoning field states only that it is "a standard French département with no name match among existing polities and no boundary feature found." This page therefore documents the routing decision's own justification rather than a dataset it cannot independently verify counts for. Previously this territory's data (whatever series feed the FRK23 admin code) would have had no dedicated polity to route to, since no Drôme-named or Drôme-boundaried row existed in the table before this entry, and routing it instead to the national FRA-1919-2025 row would silently attribute département-level statistics to the whole of France, a roughly 80x territory overstatement (551,695 km² national vs. ~6,530 km² département). What confirms this is a distinct reporting/administrative entity: Drôme is one of France's 96 metropolitan départements, a first-order administrative division with its own INSEE code (26), préfecture, and elected conseil départemental -- an uncontroversial, well-documented distinct administrative unit, not a name coincidence or a defunct historical claim.

Its modern area is approximately **6,530 km²**. ## Predecessors and successors

This entry has no predecessor: Drôme was created directly by the March 1790 Revolutionary reorganisation from parts of the former province of Dauphiné (plus a small enclave of the former Comtat Venaissin/Principality of Orange around the town of Grignan), not by splitting or renaming an earlier database polity, and no prior régime-era row for this territory exists in the table. It has no successor either: the département has not been abolished, merged, or split, and remains a live administrative unit of France through 2025, so end_year is the open-present convention used across this database rather than a transition to a successor code.

## Decisions

### d-start-year-1800-not-1790

**start_year set to 1800, not 1790, to satisfy container tiling**

The routing decision proposed 1790 as the start year, following the standard rule that French départements were created by the Revolutionary reorganisation of March 1790 (Drôme included, formed largely from the eastern part of the former province of Dauphiné). However, the earliest France container row in this database, FRA-1800-1871, itself only begins in 1800 -- there is no France national row covering 1790-1800 to container against. Since the containment gate rejects any edge whose interval falls outside the container's own span, a 1790 start would leave a decade of this entry uncontained. Rather than invent a container edge that points at a row that doesn't exist, the pragmatic choice here is to set start_year to 1800, matching the earliest available container, and flag the true 1790 creation date as an open question about the France national chain's own coverage rather than something this département page can fix unilaterally. If a future FRA row extending back to 1790 is added, this page's start_year should move down to match, and the code would need to change to FRA-DRO-1790-2025 with it.

### d-subunit-code-dro

**Subunit code DRO chosen for the dominant <ISO3>-<SUBUNIT>-<start>-<end> pattern**

France has no existing subnational rows, so there is no in-country precedent to follow, but the cross-country pattern is overwhelming: 57 of 66 subnational rows use <ISO3>-<SUBUNIT>-<start>-<end> (e.g. ESP-AS-1833-2025, ESP-CA-1833-2025, DZA-CVD-1902-1919). Drôme is an ordinary département with no independent name of its own outside the modern French administrative system -- it is not a bespoke historical territory like Alaska or Hyderabad -- so the bespoke-code pattern (3 of 66 rows) does not apply. DRO was chosen as a short, legible abbreviation of Drôme; it does not collide with any other polity code in the table.

## Open questions

### oq-france-container-gap-1790-1800

**France's own container chain does not reach back to the 1790 département creation date**

Drôme, like all 83 original French départements, was created in March 1790 by the Revolutionary Assembly's reorganisation of the kingdom's provinces. This database's earliest France national row, FRA-1800-1871, only starts in 1800, so this entry's start_year was set to 1800 to keep the container chain gapless (see decision d-start-year-1800-not-1790) rather than to reflect the actual founding date. If a future pass extends the France national chain back to 1790 (or adds a distinct 1790-1800 row for the First Republic / Consulate period), this page should be re-spanned to FRA-DRO-1790-2025 and its start_year corrected. Until then, ten years of this département's actual existence are not represented by any row in the database.

### oq-gadm-france-not-fetched

**GADM 4.1 admin-1 data for France is registered but not present on disk**

The routing decision found that gadm-4.1-adm1 is registered in scripts/sources.yaml and does digitise French départements at the global level, but the locally fetched subset covers only 81 countries and does not include France. No feature can be assigned today, so polygon_status is unassigned and polygon_feature_id is null. The fix is to fetch or extend the local GADM adm1 extract to include FRA -- once that is done, the correct feature (matching INSEE department code 26, Drôme) should be identified and this entry updated to polygon_status: assigned. Vintage risk for that eventual polygon is low: French département boundaries have been essentially stable since 1790 for Drôme specifically (no annexation, no boundary revision on the scale of Alsace-Lorraine or the post-1943 splits seen in other départements), so a modern GADM boundary should be a faithful proxy across the whole 1800-2025 span once fetched.

### oq-no-boundary-revisions-confirmed

**No documented boundary revisions checked against INSEE administrative history**

This page assumes Drôme's boundary has been stable since 1790 based on general knowledge that it was not among the départements affected by 1943 wartime splits (e.g. Isère was not split, unlike Seine or Corse), but this has not been verified against INSEE's official code history (COG) or IGN's historical boundary files. If a minor boundary adjustment did occur (cantonal reorganisations do not affect département limits, but occasional inter-département transfers of communes have happened elsewhere in France), the single-polygon-for-the-whole-span assumption implicit in leaving no period subdivisions would be wrong and this entry might eventually need splitting.
