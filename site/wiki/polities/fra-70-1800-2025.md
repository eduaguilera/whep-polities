# Haute-Saône

## Summary

This entry represents Haute-Saône, a French département in the Bourgogne-Franche-Comté region, occupying the eastern part of the former province of Franche-Comté between the Vosges foothills to the north and the Doubs valley to the south, centred on its prefecture Vesoul. It is coded as a `subnational` polity because a département is an administrative subdivision of France, not a sovereign state or a distinct internationally-recognised territory -- France's sovereignty over this area is continuous and undisputed throughout the entry's span, and the national FRA rows in this table already carry that sovereignty claim for the whole country. This row exists solely to carry a *sub-national reporting territory*: statistics keyed to "Haute-Saône" or its Eurostat NUTS3 code FRC23 specifically, as opposed to all-France totals, need somewhere to route that isn't the national polygon. The entry follows the country convention's default start rule (1790, the year of the Revolutionary départements reform) as adjusted here to 1800 to match the earliest available French national container row (see decisions), and runs to the open end_year 2025 since the département remains an active administrative unit of France today with no successor.

**Why this entry exists.** This page implements the routing decision for unit FRA-FRC23 (admin_name "FRC23", country France), which resolved via create_new because no existing FRA polity IS this territory -- the national FRA rows (FRA-1800-1871, FRA-1871-1919, FRA-1919-2025) describe the whole country, and a département cannot be represented by its country's row; the three existing FRA-* candidates the routing decision considered are all national-level rows covering different Alsace-Lorraine configurations, which contain but are not equal to Haute-Saône. Before this decision, any data keyed to Haute-Saône specifically was, by construction of the routing pipeline, unmatched rather than misrouted -- match_existing was excluded outright since no existing row's territory equals this département's. What confirms Haute-Saône as a distinct, statistically-reported entity rather than an arbitrary subdivision is that it is one of the original Revolutionary départements of 1790 and has been tabulated in French statistical yearbooks (INSEE and predecessors, and Eurostat's NUTS3 series under FRC23) as a discrete unit under code 70 ever since -- the same status INSEE gives every other département. This entry's span (1790-2025 per the routing decision, adjusted here to 1800-2025, see decisions) covers the full administrative existence rather than a narrower data span, so a single create_new polity suffices.

## Territorial extent

Polygon status: Not yet assigned. No polygon available in the GeoPackage for this period. The routing decision already established this is a `new_source_needed` case: no source registered in scripts/sources.yaml digitises French départements at this resolution. gadm-4.1-adm1's local file is a curated subset of 81 countries that omits France entirely (even though GADM's global release does cover French départements at admin-1); cshapes-2.0 and cshapes-europe are country-level only and cannot supply a sub-national boundary. The standard remedy would be to register GADM's global admin-1 layer or French IGN's ADMIN-EXPRESS product, neither of which is on disk in this repository today.

Territory description: Haute-Saône covers roughly 5,360 km² in the northern part of Bourgogne-Franche-Comté, bordering the Vosges département to the north, the Territoire de Belfort and Haut-Rhin to the northeast, Doubs to the southeast, Jura and Côte-d'Or to the south and southwest, and Haute-Marne to the west. Its prefecture is Vesoul; other principal towns include Lure and Gray. The département straddles the upper Saône river basin and the southern edge of the Vosges massif, with the Langres plateau touching its western fringe. This description is drawn from present-day knowledge of the département's location and standard reference figures for its area, not measured from any polygon attached to this entry, since none is yet assigned.

## Predecessors and successors

Haute-Saône has no predecessor row: it is created directly by this entry as one of the original ~83 Revolutionary départements of 1790 (adjusted here to a 1800 start, see decisions), and no earlier polity in this database claims to represent this specific territory. It has no successor either: the département remains an active administrative and statistical unit of France today, unaffected by any of the reorganisations (Alsace-Lorraine's 1871/1919 changes of hands, the 1871-1922 separation of the Territoire de Belfort from neighbouring Haut-Rhin, Corsica's 1975 split, or decolonisation of the overseas départements) that produced predecessor/successor chains elsewhere in the FRA family. Its end_year of 2025 is open only because it shares the containing national row FRA-1919-2025's own open end, not because of any territorial event.

## Decisions

### d-start-year-1800-not-1790

**Start year set to 1800 to match the earliest FRA container row, not the département's 1790 creation**

The routing decision's span_basis argues for the country convention's default start rule (1790, the year of the Revolutionary départements reform), since Haute-Saône is not among the four enumerated departure cases (Belfort, Alsace-Lorraine départements, Corse split, overseas départements). But no FRA national polity row in this database covers 1790-1800 -- the earliest is FRA-1800-1871 -- and the containment gate rejects a container edge that falls outside the container's own span. I therefore set start_year to 1800, ten years later than the routing decision's proposed 1790, so that the container chain (FRA-1800-1871, FRA-1871-1919, FRA-1919-2025) tiles the entry's whole span with no gap. This exactly follows the precedent set by sibling entries FRA-18-1800-2025 (Cher), FRA-21-1800-2025 (Côte-d'Or), FRA-77-1800-2025 (Seine-et-Marne) and FRA-89-1800-2025 (Yonne), all of which face the identical 1790-vs-1800 mismatch and resolve it the same way. The uncovered 1790-1800 decade is recorded as an open question below.

### d-code-uses-insee-70-not-frc23

**Subunit code is the INSEE/ISO 3166-2 numeric code 70, not the routing decision's NUTS3 admin_name FRC23**

The routing decision labels this unit 'FRC23' (a Eurostat NUTS3 code for a Bourgogne-Franche-Comté département) and its unit_id 'FRA-FRC23'. Following the precedent set by FRA-18, FRA-21, FRA-77 and FRA-89, I used the INSEE/ISO 3166-2:FR two-digit numeric code 70 for Haute-Saône rather than the NUTS3 code, since 70 is the identifier a reader recognises from French postcodes (70xxx), car plates, and INSEE statistical tables, whereas FRC23 is not in ordinary public use. This gives the code FRA-70-1800-2025, matching the dominant <ISO3>-<SUBUNIT>-<start>-<end> pattern with a subunit token a reader can actually place.

### d-polygon-unassigned-not-proxy

**Polygon left unassigned rather than proxied from the national polygon or a neighbouring département**

The routing decision's polygon_route is new_source_needed: no registered source in scripts/sources.yaml digitises French départements at this resolution. gadm-4.1-adm1's local file is a curated 81-country subset that excludes France (even though GADM's global admin-1 release does cover French départements), and cshapes-2.0/cshapes-europe are country-level only. I did not substitute the national FRA polygon or a hand-drawn union as a stopgap proxy, because doing so would defeat this row's purpose, which is to isolate Haute-Saône's own reporting territory from the national one. polygon_source is set to the 'none' sentinel already used by FRA-18, FRA-21, FRA-77, FRA-89, and other unassigned départements in this table.

## Open questions

### oq-pre-1800-gap-uncovered

**The 1790-1800 decade of Haute-Saône's existence is not represented by this entry or any container**

Haute-Saône was created in 1790 by the Revolutionary départements reform, carved from the eastern part of the former province of Franche-Comté (the bailliages of Vesoul, Gray and Lure). That is ten years before this entry's start_year of 1800. The gap exists because no FRA national polity row in this database covers 1790-1800 -- the earliest is FRA-1800-1871. If a future entry adds an FRA-1790-1800 (or similar) national row closing that gap, this entry's start_year should be pulled back to 1790 with a matching container edge and the polity_code updated to FRA-70-1790-2025. Until then, any data keyed to Haute-Saône in 1790-1799 has nowhere to route. The same open question already exists on sibling entries FRA-18, FRA-21, FRA-77 and FRA-89, so a fix would likely apply to several France département rows at once.

### oq-territoire-de-belfort-boundary-interaction-unverified

**Haute-Saône's eastern boundary with the Territoire de Belfort after 1871-1922 has not been checked for a territorial adjustment**

The Territoire de Belfort was created in 1871-1922 from the arrondissement of Belfort, which before 1871 belonged to the Haut-Rhin département, not Haute-Saône -- so unlike Haut-Rhin, Haute-Saône should be unaffected by the 1871 partition. However, this has been asserted here from general knowledge of French administrative geography rather than checked against a source describing the exact 1871 boundary line between Haute-Saône and the newly separated Territoire de Belfort. If any canton on their shared border was in fact reassigned during this reorganisation, the container basis for FRA-1871-1919 above would need correction, and this entry's own boundary for that era would be affected.

### oq-nuts-vs-insee-code-mismatch

**The routing decision's admin_name (FRC23, a NUTS3 code) does not match the INSEE code (70) used as this entry's subunit identifier**

The decision this page implements labels the unit 'FRC23', a Eurostat NUTS3 statistical code for a Bourgogne-Franche-Comté département, while this entry uses INSEE/ISO 3166-2:FR numeric code 70 as the polity_code subunit (see decisions). I have treated FRC23 and INSEE 70 as denoting the same territory (Haute-Saône) based on standard NUTS-to-département crosswalks, but this crosswalk has not been independently verified against an authoritative Eurostat correspondence table within this pipeline run. Bourgogne-Franche-Comté also contains Côte-d'Or, Nièvre, Saône-et-Loire, Doubs, Jura, Yonne and Territoire de Belfort, several of which are NUTS3-adjacent in code order to FRC23; if the source data's FRC23 rows in fact refer to a different département in this region, this entry would be misrouted.
