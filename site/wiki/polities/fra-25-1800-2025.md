# Doubs

## Summary

This entry represents Doubs, a French département in the Bourgogne-Franche-Comté region, on France's eastern frontier with Switzerland, centred on its prefecture Besançon and running along the Doubs river valley and the Jura mountain chain from the Swiss border west toward the Saône plain. It is coded as a `subnational` polity because a département is an administrative subdivision of France, not a sovereign state or a distinct internationally-recognised territory -- France's sovereignty over this area is continuous and undisputed throughout the entry's span, and the national FRA rows in this table already carry that sovereignty claim for the whole country. This row exists solely to carry a *sub-national reporting territory*: statistics keyed to "Doubs" or its Eurostat NUTS3 code FRC21 specifically, as opposed to all-France totals, need somewhere to route that isn't the national polygon. The entry follows the country convention's default start rule (1790, the year of the Revolutionary départements reform) as adjusted here to 1800 to match the earliest available French national container row (see decisions), and runs to the open end_year 2025 since the département remains an active administrative unit of France today with no successor.

**Why this entry exists.** This page implements the routing decision for unit FRA-FRC21 (admin_name "FRC21", country France), which resolved via create_new because no existing FRA polity IS this territory -- the national FRA rows (FRA-1800-1871, FRA-1871-1919, FRA-1919-2025) describe the whole country, and a département cannot be represented by its country's row; the three existing FRA-* candidates the routing decision considered are all national-level rows covering different Alsace-Lorraine configurations, which contain but are not equal to Doubs. Before this decision, any data keyed to Doubs specifically was, by construction of the routing pipeline, unmatched rather than misrouted -- match_existing was excluded outright since no existing row's territory equals this département's. What confirms Doubs as a distinct, statistically-reported entity rather than an arbitrary subdivision is that it is one of the original Revolutionary départements of 1790 and has been tabulated in French statistical yearbooks (INSEE and predecessors, and Eurostat's NUTS3 series under FRC21) as a discrete unit under code 25 ever since -- the same status INSEE gives every other département. This entry's span (1790-2025 per the routing decision, adjusted here to 1800-2025, see decisions) covers the full administrative existence rather than a narrower data span, so a single create_new polity suffices.

## Territorial extent

Polygon status: Not yet assigned. No polygon available in the GeoPackage for this period. The routing decision already established this is a `new_source_needed` case: no source registered in scripts/sources.yaml digitises French départements at this resolution. gadm-4.1-adm1's local file is a curated subset of 81 countries that omits France entirely (even though GADM's global release does cover French départements at admin-1); cshapes-2.0 and cshapes-europe are country-level only and cannot supply a sub-national boundary. The standard remedy would be to register GADM's global admin-2 layer or French IGN's ADMIN-EXPRESS product, neither of which is on disk in this repository today.

Territory description: Doubs covers roughly 5,234 km² in the eastern part of Bourgogne-Franche-Comté, bordering Haute-Saône to the west, Jura to the south, Territoire de Belfort to the north, and Switzerland (cantons of Jura and Neuchâtel) to the east. Its prefecture is Besançon; it includes the Doubs river's horseshoe loop around Besançon's citadel, the Jura mountain ridges toward the Swiss frontier, and the industrial Montbéliard-Belfort corridor associated with Peugeot's automotive manufacturing. This description is drawn from present-day knowledge of the département's location and standard reference figures for its area, not measured from any polygon attached to this entry, since none is yet assigned.

It has no successor either: the département remains an active administrative and statistical unit of France today, unaffected by any of the reorganisations (Alsace-Lorraine's 1871/1919 changes of hands, Corsica's 1975 split, the 1968 Paris petite couronne restructuring, or decolonisation of the overseas départements) that produced predecessor/successor chains elsewhere in the FRA family. ## Decisions

### d-start-year-1800-not-1790

**start_year set to 1800, not the routing decision's proposed 1790, to match the earliest available FRA container row**

The routing decision's span_basis argues for 1790 (the year of the Revolutionary départements reform) under the country convention's default start rule, since Doubs is not one of the four enumerated departures (Belfort, Alsace-Lorraine, Corsica, overseas départements). But no FRA national polity row in this database covers 1790-1800 -- the earliest is FRA-1800-1871 -- and the containment gate rejects an edge falling outside either party's own span. I therefore set start_year to 1800 to match the earliest FRA container, exactly as FRA-21-1800-2025 (Côte-d'Or), FRA-18-1800-2025 (Cher) and the other sibling FRA département entries already do, rather than leaving a decade uncontained. The polity_code year (1800) equals the frontmatter start_year, satisfying the code/frontmatter equality gate. The 1790-1800 gap is recorded as an open question below, consistent with every other FRA département sibling.

### d-subunit-code-insee-25-not-frc21

**Subunit code is the INSEE/ISO 3166-2 numeric code 25, not the routing decision's NUTS3 admin_name FRC21**

The routing decision labels this unit 'FRC21' (a Eurostat NUTS3 code for a Bourgogne-Franche-Comté département) and its unit_id 'FRA-FRC21'. Following the precedent set by FRA-21-1800-2025 (Côte-d'Or, INSEE 21, NUTS3 FRC11) and FRA-18-1800-2025 (Cher), I used the INSEE/ISO 3166-2:FR two-digit numeric code 25 for Doubs rather than the NUTS3 code, since 25 is the identifier a reader recognises from French postcodes (25xxx) and car plates, whereas FRC21 is not in ordinary public use. This gives the code FRA-25-1800-2025, matching the dominant <ISO3>-<SUBUNIT>-<start>-<end> pattern with a subunit token a reader can actually place.

### d-polygon-unassigned-not-proxy

**Polygon left unassigned rather than proxied from the national polygon or a neighbouring département**

The routing decision's polygon_route is new_source_needed: no registered source in scripts/sources.yaml digitises French départements at this resolution. gadm-4.1-adm1's local file is a curated 81-country subset that excludes France, and cshapes-2.0/cshapes-europe are country-level only. I did not substitute the national FRA polygon or a hand-drawn union as a stopgap proxy, because doing so would defeat this row's purpose, which is to isolate Doubs's own reporting territory from the national one. polygon_source is set to the 'none' sentinel already used by FRA-21-1800-2025, FRA-18-1800-2025, and other unassigned FRA sibling rows in this table.

## Open questions

### oq-pre-1800-gap-uncovered

**The 1790-1800 decade of Doubs's existence is not represented by this entry or any container**

Doubs was created in 1790 by the Revolutionary départements reform, one of the original tranche of roughly 83 départements, carved from the eastern part of the former province of Franche-Comté (annexed to France in 1678 by the Treaty of Nijmegen, well before the Revolution). That is ten years before this entry's start_year of 1800. The gap exists because no FRA national polity row in this database covers 1790-1800 -- the earliest is FRA-1800-1871. If a future entry adds an FRA-1790-1800 (or similar) national row closing that gap, this entry's start_year should be pulled back to 1790 with a matching container edge and the polity_code updated to FRA-25-1790-2025. Until then, any data keyed to Doubs in 1790-1799 has nowhere to route. The same open question already exists on sibling entries FRA-21-1800-2025 and FRA-18-1800-2025, so a fix would likely apply to several France département rows at once.

### oq-1871-border-adjustment-unverified

**Whether Doubs lost any commune-level territory in the 1871 border redrawing near the new German frontier is not checked**

Doubs sits well south of Alsace-Lorraine and did not lose territory to the German Empire in 1871 in the way Territoire de Belfort's neighbour Haut-Rhin did, and this entry's container basis for FRA-1871-1919 asserts that Doubs's own territory was untouched. But Doubs does border the Territoire de Belfort, which was carved out of the remaining, unceded fragment of Haut-Rhin in 1871 specifically to keep it French; whether any 1871-era boundary commission moved communes between Doubs and the new Territoire de Belfort (as opposed to purely reorganising the ceded Haut-Rhin remnant) has not been checked against a primary source here. If such a transfer occurred it would be a small, localised change rather than the department-scale event the container basis implies, but it is currently asserted from general knowledge of French administrative geography, not verified.

### oq-nuts-vs-insee-code-mismatch

**The routing decision's admin_name (FRC21, a NUTS3 code) does not match the INSEE code (25) used as this entry's subunit identifier**

The decision this page implements labels the unit 'FRC21', a Eurostat NUTS3 statistical code for a Bourgogne-Franche-Comté département, while this entry uses INSEE/ISO 3166-2:FR numeric code 25 as the polity_code subunit (see decisions). I have treated FRC21 and INSEE 25 as denoting the same territory (Doubs) based on standard NUTS-to-département crosswalks, but this crosswalk has not been independently verified against an authoritative Eurostat correspondence table within this pipeline run. Bourgogne-Franche-Comté also contains Côte-d'Or, Nièvre, Saône-et-Loire, Yonne, Jura, Haute-Saône and Territoire de Belfort, several of which are NUTS3-adjacent in code order to FRC21; if the source data's FRC21 rows in fact refer to a different département in this region, this entry would be misrouted.

### oq-departement-boundary-stability-unverified

**Doubs's boundary stability across 1800-2025 is asserted from general knowledge, not checked against a source**

The routing decision's span_basis argues Doubs is not among the four enumerated departure cases and so follows the unbroken-existence default rule, but this is general knowledge of French administrative geography rather than a cited source. Doubs's borders with Haute-Saône, Jura, Territoire de Belfort and Switzerland (Canton of Jura, Neuchâtel) have not been checked here for any 19th- or 20th-century commune-transfer adjustments. When a polygon source is finally registered for this row, its boundary vintage should be checked against a specific year rather than assumed identical to the present-day shape across the whole 1800-2025 span.
