# Cher

## Summary

This entry represents Cher, a French département in the Centre-Val de Loire region, in the historic province of Berry, south of Paris and centred on the Loire valley town of Bourges. It is coded as a `subnational` polity because a département is an administrative subdivision of France, not a sovereign state or a distinct internationally-recognised territory -- France's sovereignty over this area is continuous and undisputed throughout the entry's span, and the national FRA rows in this table already carry that sovereignty claim for the whole country. This row exists solely to carry a *sub-national reporting territory*: statistics keyed to "Cher" or its Eurostat NUTS3 code FRB01 specifically, as opposed to all-France totals, need somewhere to route that isn't the national polygon. The entry follows the country convention's default start rule (1790, the year of the Revolutionary départements reform) as adjusted here to 1800 to match the earliest available French national container row (see decisions), and runs to the open end_year 2025 since the département remains an active administrative unit of France today with no successor.

**Why this entry exists.** This page implements the routing decision for unit FRA-FRB01 (admin_name "FRB01", country France), which resolved via create_new because no existing FRA polity IS this territory -- the national FRA rows (FRA-1800-1871, FRA-1871-1919, FRA-1919-2025) describe the whole country, and a département cannot be represented by its country's row. Before this decision the data for this unit was, by construction of the routing pipeline, unmatched rather than misrouted -- match_existing was excluded outright since no existing row's territory equals Cher's. What confirms Cher as a distinct, statistically-reported entity rather than an arbitrary subdivision is that it is one of the original ~83 départements created by the 1790 Revolutionary reform and has been administered, and tabulated in French statistical yearbooks (INSEE and its predecessors, and Eurostat's NUTS3 series under FRB01) as a discrete unit under the numeric code 18 ever since -- the same status that INSEE gives every other département in the country's statistical apparatus. This entry's span (1790-2025, adjusted here to 1800-2025, see decisions) covers the full administrative existence rather than being trimmed to any narrower data span, so a single create_new polity suffices with no back_cast or matched segments.

## Territorial extent

**Polygon status:** Not yet assigned. No polygon available in the GeoPackage for this period. The routing decision already established this is a `new_source_needed` case: no source registered in scripts/sources.yaml digitises French départements. gadm-4.1-adm1's local file is a curated subset that omits France entirely (even though GADM's global release does cover French départements); cshapes-2.0 and cshapes-europe are country-level only and cannot supply a sub-national boundary. The standard remedy would be to register GADM's global admin-2 layer or French IGN's ADMIN-EXPRESS product, neither of which is on disk in this repository today.

**Territory description:** Cher occupies the southern part of the Centre-Val de Loire region, in the historic province of Berry. On a modern map it is bounded by the départements of Loiret and Loir-et-Cher to the north and west, Indre to the southwest, Creuse and Allier to the south, and Nievre to the east; its administrative seat (préfecture) is Bourges. It covers approximately 7,235 km2 -- this figure is a published administrative-area statistic for the modern département, not a measurement from any polygon attached to this entry, since no polygon is yet assigned (see polygon status above). The département is largely agricultural (cereals, vineyards around Sancerre and Menetou-Salon) with the Sologne's forested northern fringe and the Loire and Cher rivers crossing its territory.

## Predecessors and successors

Cher has no predecessor or successor polity in this table: it was created directly by the 1790 Revolutionary départements reform (predating this database's coverage, see the open question on the 1790-1800 gap) and has continued as an administrative unit of France without interruption through 2025, so both fields are empty. It is not known to have been split off from, merged into, or ceded to any other polity tracked here, and it was not among the départements affected by the 1871 Alsace-Lorraine cession or its 1919 return.

## Sourced claims

- INSEE and the ISO 3166-2:FR standard both identify Cher with the numeric code 18, distinct from the Eurostat NUTS3 code FRB01 used in the source unit this entry routes.
- The routing decision for unit FRA-FRB01 states Cher is not among the 4 listed departure cases (Belfort, Alsace-Lorraine, Corse, overseas départements) in the country convention, so the default 1790 start rule applies to it rather than a bespoke span.

## Decisions

### d-start-year-1800-not-1790

**start_year set to 1800, not the proposed 1790, because no container exists for the earlier decade**

The routing decision's span_basis argues for 1790, the year of the Revolutionary départements reform that created Cher. That is very likely correct as administrative history, but this database's earliest French national row is FRA-1800-1871 -- there is no FRA row of any kind covering 1790-1800, and the containment gate rejects an edge that falls outside either party's span. Rather than leave a decade uncontained, or invent a container edge citing a national polity that does not exist in the table, I moved start_year to 1800 to match the earliest available container, exactly as the sibling entry FRA-77-1800-2025 (Seine-et-Marne) already did for the same reason. The polity code year (1800) and the frontmatter start_year (1800) are kept equal, satisfying the gate that ties code years to frontmatter years. If a pre-1800 French national polity is added later, this entry's start_year should be revisited alongside it -- see the open question below.

### d-subunit-code-18-not-abbreviation

**Subunit code is the INSEE/ISO 3166-2 numeric code 18, not a letter abbreviation or the NUTS3 code from the routing decision**

The dominant pattern for subnational rows is <ISO3>-<SUBUNIT>-<start>-<end>, and the exemplar subunit codes shown (ESP-AS, ESP-CA) are ISO 3166-2 letter codes, while the routing decision's own admin_name for this unit is 'FRB01', a Eurostat NUTS3 code. France's départements do not have ISO 3166-2 letter codes in general use, and NUTS3 codes are not how French statistical sources or the public identify a département. The standard identifier for Cher, used by INSEE, La Poste, and ISO 3166-2:FR alike, is the two-digit number 18. I used FRA-18-1800-2025 rather than the NUTS3 code or an invented letter abbreviation, matching the convention already set by the sibling entry FRA-77-1800-2025 (Seine-et-Marne), since 18 is the identifier a reader would actually recognise on a map, car plate, or postcode prefix (18xxx).

### d-polygon-unassigned-not-proxy

**Polygon left unassigned rather than proxied from a neighbouring département or the national polygon**

The routing decision already worked out that no registered source in scripts/sources.yaml digitises French départements at the resolution this entry needs -- gadm-4.1-adm1's local file is a curated subset that excludes FRA, and cshapes-europe/cshapes-2.0 are country-level only. I did not attempt a coarser proxy (e.g. the national FRA polygon, or a hand-drawn union) because the whole point of this row is to isolate Cher's own reporting territory from the national one; substituting the national shape would defeat that purpose silently. polygon_source is set to the 'none' sentinel used by other unassigned rows in this table (e.g. RYU-1937-1945, BLZ-1886-1970, and sibling FRA-77-1800-2025) rather than a placeholder string, matching existing convention.

## Open questions

### oq-pre-1800-gap-uncovered

**The 1790-1800 decade of Cher's existence is not represented by this entry or any container**

Cher was created in 1790 by the Revolutionary départements reform (as one of the first tranche of ~83 départements, carved from the former province of Berry), ten years before this entry's start_year of 1800. That gap exists because no FRA national polity row in this database covers 1790-1800 -- the earliest is FRA-1800-1871. If a future entry adds an FRA-1790-1800 (or similar) national row to close that gap, this entry's start_year should be pulled back to 1790 to match, with a corresponding container edge added. Until then, any data keyed to Cher in 1790-1799 has nowhere to route. The same open question exists on the sibling entry FRA-77-1800-2025, so a fix would likely apply to several France subnational rows at once rather than this one alone.

### oq-departement-boundary-stability-unverified

**Cher's boundary stability across 1800-2025 is asserted from general knowledge, not checked against a source**

The routing decision's span_basis claims Cher is not among the four departure cases (Belfort, Alsace-Lorraine, Corse, overseas départements) and so follows the default 1790 rule with an unbroken existence, but this is general knowledge of French administrative geography rather than a cited source. Unlike Paris-region départements, Cher was not touched by the 1968 petite couronne reorganisation, but whether its perimeter has been fully stable since 1790 -- including any minor commune-level boundary adjustments with neighbouring Loiret, Nievre, Allier, Creuse, Indre, or Loir-et-Cher -- has not been verified here. When a polygon source is finally registered (see polygon status), its boundary vintage should be checked against a specific year rather than assumed identical to the present-day shape for the whole 1800-2025 span.

### oq-nuts-vs-insee-code-mismatch

**The routing decision's admin_name (FRB01, a NUTS3 code) does not match the INSEE code (18) used as this entry's subunit identifier**

The decision this page implements labels the unit 'FRB01', which is a Eurostat NUTS3 statistical code for a Centre-Val de Loire département, while this entry uses INSEE/ISO 3166-2:FR numeric code 18 as its polity_code subunit (see decisions). I have treated FRB01 and INSEE 18 as denoting the same territory (Cher) based on standard NUTS-to-département crosswalks, but this crosswalk has not been independently verified against an authoritative Eurostat correspondence table within this pipeline run. If the source data's FRB01 rows in fact refer to a different Centre-Val de Loire département (the region also contains Eure-et-Loir, Indre, Indre-et-Loire, Loiret, and Loir-et-Cher, several of which are NUTS3-adjacent in code order), this entry would be misrouted.
