# Loiret

## Summary

Loiret is one of the original ~83 départements created by the French Revolutionary administrative reform of March 1790, centered on Orléans in the Centre-Val de Loire region south of Paris, along the middle Loire river. This entry is `type: subnational` because it is a sub-national administrative division of France, not a sovereign state or a distinct reporting territory with its own international personality -- it exists only to carry data that two agricultural statistics sources tabulate at the département level rather than folding into the national French totals. Loiret is not one of the departure cases the harness's country-conventions file tracks for France (Belfort, which was carved out of Haut-Rhin after 1871; Alsace-Lorraine, annexed and returned; the 1975 Corsica split into Corse-du-Sud and Haute-Corse; or the overseas départements created in 1946), so it follows the default rule for French départements: created in 1790 and stable since. Its start_year in this entry is pinned to 1800 rather than 1790 because no FRA national container row in the polity table reaches back to 1790 -- see decisions and open questions below.

**Why this entry exists.** The routing decision this page implements (unit_id FRA-FRB06, admin_name FRB06) found data for Loiret running 1862-2023, 97.6% observed/blank (i.e. direct measurement rather than back-cast), and no existing FRA polity below the national level to route it to. The only FRA candidates in the table are the three national-era rows -- FRA-1800-1871, FRA-1871-1919, FRA-1919-2025 -- each of which contains Loiret but is not Loiret: routing département-level agricultural statistics to a national row would silently merge them into every other French département's figures for the same years, which is exactly the kind of over-aggregation this pipeline exists to catch. French départements are a standard, well-documented statistical and administrative reporting unit -- INSEE and its predecessors have published at département granularity continuously since the 19th century -- which is the historical confirmation that Loiret is a distinct, addressable reporting entity rather than an arbitrary subdivision invented for this table.

## Territorial extent

**Polygon status:** Not yet assigned. No polygon available in the GeoPackage for this period. The routing decision's polygon_route is `new_source_needed`: the two FRA sources registered in this repository, cshapes-europe and cshapes-2.0, carry only country-level French boundaries. gadm-4.1-adm1 is registered but the local file backing it is an 81-country ADM1 subset that excludes France outright, so even the region tier is unavailable, let alone the ADM2 (département) tier Loiret needs. None of the other registered sources (paine-2024, cliopatria, histogis-1860-habsburg, constructed, reporting-areas) digitise French département boundaries either. A correct polygon would come from downloading the full (unsubsetted) global GADM 4.1 ADM2 layer, or from IGN France's ADMIN-EXPRESS départements dataset, and registering it in sources.yaml -- filed as an open question below since no local file to build from exists today.

**Territory description:** Loiret is a French département in the Centre-Val de Loire region, roughly 100 km south of Paris, with its préfecture at Orléans. On a modern map it is bounded by Eure-et-Loir and Seine-et-Marne to the north, Yonne to the east, Nievre and Cher to the south, and Loir-et-Cher to the west, straddling the middle Loire valley. Its modern area is approximately **6,775 km2** (a figure drawn from published INSEE/general-reference statistics for the département, not from any geometry attached to this entry, since none is attached -- see polygon status above). The boundary has been essentially stable since the 1790 creation of the French département system, subject only to the routine minor commune-boundary adjustments common to all long-lived French administrative units.

## Decisions

### d-start-year-1800-not-1790

**Start year set to 1800, not the proposed 1790, because no FRA container reaches back that far**

The routing decision proposed start_year=1790, citing Loiret's creation in the March 1790 département reform. But the polity table's earliest FRA national row is FRA-1800-1871 (1800-1871); there is no FRA-* row covering 1790-1800, and the containment gate rejects any container edge falling outside the container's own span. Rather than leave a decade uncontained, this entry's start_year is set to 1800, matching the earliest available container. This is a containment-availability constraint, not a claim that Loiret did not exist 1790-1800 -- it plainly did, under the same boundary. If a pre-1800 FRA national row is ever added, this entry's start_year should be pulled back to 1790 to match, since the department's own history supports it. The code therefore reads FRA-LOI-1800-2025 rather than FRA-LOI-1790-2025.

### d-polity-code-alpha-abbreviation

**Used FRA-LOI-1800-2025 rather than a numeric INSEE code**

France has no existing subnational rows in the table, so there is no established FRA departmental-code precedent to follow (the harness notes this explicitly: 'Existing subnational codes for FRA (0): none'). The dominant cross-country pattern for subnational rows is <ISO3>-<SUBUNIT>-<start>-<end> with an alphabetic SUBUNIT (ESP-AS, ESP-CA, DZA-CVD), so LOI (a plain abbreviation of Loiret) was chosen over the numeric INSEE department code 45 to stay consistent with that convention, and because a bare '45' is not self-describing the way AS or CVD are.

### d-polygon-unassigned-not-proxy

**polygon_status left as unassigned, not proxy or assigned**

The routing decision's polygon_route is new_source_needed: no registered source (cshapes-europe, cshapes-2.0, gadm-4.1-adm1's local 81-country subset, paine-2024, cliopatria, histogis-1860-habsburg, constructed, reporting-areas) carries French département boundaries locally. There is nothing to proxy from within this repository's data, so polygon_status is unassigned rather than proxy -- a proxy implies borrowing a real geometry from an adjacent period or entity, which does not exist here.

## Open questions

### oq-polygon-source-needed

**No boundary geometry is available in the GeoPackage for Loiret at any period**

The two registered FRA sources (cshapes-europe, cshapes-2.0) are country-level only. The gadm-4.1-adm1 source is registered but its local file is an 81-country ADM1 subset that excludes France entirely -- so even the region level is missing, let alone the ADM2 (département) level Loiret needs. Resolving this requires either downloading the full global GADM 4.1 ADM2 layer or sourcing IGN France's ADMIN-EXPRESS départements dataset and registering it in sources.yaml. Until then this entry has no polygon and polygon_area_km2 is null; any area claim in territorial_extent above is a location description drawn from general reference statistics, not a measurement of an attached geometry.

### oq-span-crosses-three-containers

**This entry's span crosses three different national FRA containers, and the schema records only edge-level containment**

The routing_concerns field on the source decision flagged this directly: Loiret's span crosses FRA-1800-1871, FRA-1871-1919 and FRA-1919-2025. This entry uses three container edges to tile the span, which the schema supports, but it means any downstream logic that assumes a single fixed container_code per polity (as the original routing decision's flat container_code field implied) will need to consult the container list rather than a scalar field. Worth checking that whatever consumes this table's containment column already expects a list of edges rather than one value.

### oq-department-count-and-boundary-history

**Whether Loiret's boundary has had any adjustment since 1790 is asserted, not verified against a primary source**

The routing decision's span_basis and this page both assert Loiret has 'kept its present form since' its 1790 creation, based on the general fact that French départements are among the most stable subnational units in Europe. This is standard historiography but has not been checked here against INSEE's own boundary-change records (INSEE does track minor commune reassignments between departments over the 19th-20th centuries). If a future check finds a boundary revision, the single polygon-proxy assumption implicit in eventually reusing one modern shape across 1800-2025 would need to be split into periods.
