# Haute-Vienne (département)

## Summary

Haute-Vienne is one of the original French départements, created on 4 March 1790 out of part of the former province of Limousin, with its préfecture at Limoges. It has kept essentially the same boundary since creation: it was not among the départements affected by the loss/return of Alsace-Lorraine (1871/1919), the 1860 annexation of Savoie/Nice, the 1793 secession of Corse, or the post-1946 creation of the overseas départements — the four categories of departure from the default 1790 start rule used for French département entries in this database. This entry uses type: subnational deliberately, so it sits under the national FRA chain rather than competing with it: the FRA-* rows in the table are national totals (France with/without Alsace-Lorraine across 1800-1871-1919-2025), and a département is not its country. The entry's start_year is set to 1800 rather than 1790 because the earliest national container row on file, FRA-1800-1871, begins in 1800; setting start_year to the département's true 1790 creation date would leave a decade (1790-1800) with no container row to tile against, which the containment gate rejects. This is a data-availability compromise, not a claim that the département did not exist 1790-1800.

**Why this entry exists.** This entry captures unit FRA-FRI23 (admin_name "FRI23", INSEE department code 87) from the country's subnational data ingest: observed and luh2_residual measurements spanning 1862-2023 (per the routing decision), i.e. real, dated territorial measurement of Haute-Vienne throughout that span, with no back-cast needed since the département has existed continuously since 1790. Before this entry, rows for Haute-Vienne had no dedicated polity to route to: the only FRA candidates in the table are the three national-era rows (FRA-1800-1871, FRA-1871-1919, FRA-1919-2025), none of which represent a sub-national unit, so routing Haute-Vienne data there would have folded département-level statistics into national totals, silently misrepresenting a smaller reporting territory as the whole of France. A separate wiki page, FRA-87-1800-2025, already exists in the wiki/polities/ directory under a similar code for what appears to be the same département, but its row does not appear in the built polities table (data/final/polities_database.csv) — it is an orphaned or superseded page, not evidence that Haute-Vienne already has a live entry. That naming collision is why this entry uses the FRA-HVN- prefix instead of FRA-87-. Confirmation that Haute-Vienne is treated as a distinct statistical/administrative unit, separate from France as a whole, comes from INSEE, which has published département-level agricultural and demographic statistics for Haute-Vienne (code 87) continuously since the département's creation — the same administrative geography that French national statistical yearbooks (e.g. Annuaire statistique de la France) report by département, distinct from national aggregates.

## Territorial extent

**Polygon status:** Not yet assigned. No polygon available in the GeoPackage for this period. The routing decision's polygon_route was new_source_needed: no registered source in this repository digitises French sub-national (département) boundaries. The registered gadm-4.1-adm1 file is a curated 81-country subset that excludes France entirely (0 French features), so although GADM as a project does publish France at adm2 (département) level, that data is not present on disk here. No other registered source (cshapes-2.0, cshapes-europe, paine-2024, cliopatria, histogis-1860-habsburg, reporting-areas, constructed) carries French sub-national geometry, and there is no combination of registered features that could construct a Haute-Vienne boundary. polygon_source is therefore `none` and polygon_status is `unassigned`, per the rule that new_source_needed routes must not carry a registered-looking slug.

**Territory description:** Haute-Vienne is a département in west-central France (historic Limousin region, now part of Nouvelle-Aquitaine), bordering Charente, Vienne, Indre, Creuse, Corrèze and Dordogne. Its préfecture is Limoges. A reader can locate it on a modern map as the area roughly between Limoges (its largest city, in the north-central part of the département) and the surrounding rural Limousin plateau, bounded to the east by the Massif Central foothills. The département's modern area is approximately **5,520 km²** (INSEE figure for the current administrative boundary). No polygon is attached to this entry, so no geometry-derived area is reported; the 5,520 km² figure is the officially published territory size, not a measurement of any attached shape. French département boundaries have been essentially stable since their 1790 creation, so this figure should hold for nearly the full 1800-2025 span, though it is stated here as the modern reference value rather than verified for every historical sub-period.

No successor: it remains a current département of France as of 2025, so successor is empty and end_year is the open-ended 2025 convention value used for still-current French sub-national entries, matching the end_year used on the national FRA-1919-2025 row it sits under.

## Decisions

### d-start-year-1800-not-1790

**start_year set to 1800, not the department's true 1790 creation date**

The country convention default for French départements not among the four listed exceptions (Belfort, Alsace-Lorraine, Corse split, overseas départements) is start_year 1790, matching the département's actual creation date. However, the earliest national FRA container row present in the built polities table is FRA-1800-1871 (data/final/polities_database.csv row 284); there is no FRA container row covering 1790-1800. The containment gate rejects a container edge whose interval falls outside either party's own span, so a container edge for 1790-1800 cannot be constructed against any existing FRA row. Rather than leave a decade uncontained (which would fail the tiling requirement that container edges cover the whole start_year-end_year span with no gap), this entry sets start_year to 1800 to align exactly with the earliest available container. This is recorded as an open question below rather than silently applied, since it means the entry's declared span understates the département's real administrative history by ten years.

### d-code-fra-hvn-not-fra-87

**Used FRA-HVN- prefix instead of the more natural FRA-87- (INSEE department number)**

The task instructions state that polity_code FRA-87-1800-2025 already has a page in wiki/polities/, held by an entry whose row is not present in the built polities table (data/final/polities_database.csv) — i.e., an orphaned or stale page rather than a live conflicting entry. To avoid colliding with that existing file and to keep this new page's code free and unambiguous, this entry uses the abbreviation FRA-HVN- (from Haute-Vienne) instead of the INSEE numeric code 87. This otherwise follows the dominant <ISO3>-<SUBUNIT>-<start>-<end> pattern used by 57 of 66 subnational rows in the table (e.g. ESP-AS-1833-2025), just with a different subunit token than the department's official number.

## Open questions

### oq-1790-1800-gap-uncontained

**Ten years of Haute-Vienne's real administrative history (1790-1800) are outside this entry's span**

Haute-Vienne was created in 1790, but this entry's start_year is set to 1800 solely because no FRA container row exists for 1790-1800 (see decision d-start-year-1800-not-1790). If a future ingest adds an earlier national FRA container row (e.g. FRA-1790-1800 or an extension of the earliest existing row's start_year back to 1790), this entry's start_year and polity_code should be revised to FRA-HVN-1790-2025 to restore the full historical span and stay code-consistent with the frontmatter years, as the containment gate requires.

### oq-no-polygon-source-identified

**No département-level polygon source is registered anywhere in this repository**

The routing decision identified GADM's global adm2 layer (or French IGN Admin Express open data) as the most natural fix, but neither is currently registered or fetched in this repository, and GADM's licence for redistribution/derivative use was not verified in the routing session. Until one of these is registered and fetched, this entry and any other French département-level entries will remain polygon_status: unassigned. Whoever fetches a French adm2 source should also check whether it should be added as a general registered source (benefiting all French département entries) rather than a one-off construction limited to Haute-Vienne.

### oq-boundary-stability-unverified

**5,520 km² territory figure is the modern boundary, not verified against 1800-1862 boundaries**

The 5,520 km² area cited is INSEE's current published figure. French département boundaries are widely described as stable since 1790, but this has not been checked here against any historical French cadastral or administrative source for the 1800-1862 portion of this entry's span (before the observed mitchell/fao-style data begins in 1862 per the routing decision). If any commune-level boundary adjustments occurred in Haute-Vienne between 1800 and 1862, the true historical area could differ slightly from the modern figure.

### oq-overlap-with-stale-fra-87-page

**Whether the stale FRA-87-1800-2025 page should be deleted or merged rather than left alongside this new entry**

wiki/polities/ contains a page for polity_code FRA-87-1800-2025 whose row does not appear in the built polities table. It is unclear from this session whether that page is simply stale (safe to delete), mid-edit, or represents a naming convention this database intended to standardize on (numeric INSEE codes) that this entry's FRA-HVN- code now diverges from. Resolving that would avoid two pages describing what may be the same territory under different naming schemes going forward.
