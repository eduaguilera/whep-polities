# Yonne

## Summary

This entry represents Yonne, a French département in the Bourgogne-Franche-Comté region, straddling the historical boundary of Burgundy, Champagne, Île-de-France and Orléanais, centred on its prefecture Auxerre and running from the Sénonais in the north to the vineyard slopes of Chablis and the fringes of the Morvan in the south. It is coded as a `subnational` polity because a département is an administrative subdivision of France, not a sovereign state or a distinct internationally-recognised territory -- France's sovereignty over this area is continuous and undisputed throughout the entry's span, and the national FRA rows in this table already carry that sovereignty claim for the whole country. This row exists solely to carry a *sub-national reporting territory*: statistics keyed to "Yonne" or its Eurostat NUTS3 code FRC14 specifically, as opposed to all-France totals, need somewhere to route that isn't the national polygon. The entry follows the country convention's default start rule (1790, the year of the Revolutionary départements reform) as adjusted here to 1800 to match the earliest available French national container row (see decisions), and runs to the open end_year 2025 since the département remains an active administrative unit of France today with no successor.

**Why this entry exists.** This page implements the routing decision for unit FRA-FRC14 (admin_name "FRC14", country France), which resolved via create_new because no existing FRA polity IS this territory -- the national FRA rows (FRA-1800-1871, FRA-1871-1919, FRA-1919-2025) describe the whole country, and a département cannot be represented by its country's row; the three existing FRA-* candidates the routing decision considered are all national-level rows covering different Alsace-Lorraine configurations, which contain but are not equal to Yonne. Before this decision, any data keyed to Yonne specifically was, by construction of the routing pipeline, unmatched rather than misrouted -- match_existing was excluded outright since no existing row's territory equals this département's. What confirms Yonne as a distinct, statistically-reported entity rather than an arbitrary subdivision is that it is one of the original Revolutionary départements of 1790 and has been tabulated in French statistical yearbooks (INSEE and predecessors, and Eurostat's NUTS3 series under FRC14) as a discrete unit under code 89 ever since -- the same status INSEE gives every other département. This entry's span (1790-2025 per the routing decision, adjusted here to 1800-2025, see decisions) covers the full administrative existence rather than a narrower data span, so a single create_new polity suffices.

## Territorial extent

Polygon status: Not yet assigned. No polygon available in the GeoPackage for this period. The routing decision already established this is a `new_source_needed` case: no source registered in scripts/sources.yaml digitises French départements at this resolution. gadm-4.1-adm1's local file is a curated subset of 81 countries that omits France entirely (even though GADM's global release does cover French départements at admin-1); cshapes-2.0 and cshapes-europe are country-level only and cannot supply a sub-national boundary. The standard remedy would be to register GADM's global admin-1 layer or French IGN's ADMIN-EXPRESS product, neither of which is on disk in this repository today.

Territory description: Yonne covers roughly 7,430 km² in the western part of Bourgogne-Franche-Comté, bordering Loiret and Seine-et-Marne to the west and northwest, Aube to the north, Côte-d'Or to the east, and Nièvre to the south. Its prefecture is Auxerre; it includes the Sénonais plain in the north around Sens, the Chablis wine-producing area east of Auxerre, and the northern fringe of the Morvan hills in the south around Avallon. This description is drawn from present-day knowledge of the département's location and standard reference figures for its area, not measured from any polygon attached to this entry, since none is yet assigned.

## Decisions

### d-start-year-1800-not-1790

**Start year set to 1800 to match the earliest FRA container row, not the département's 1790 creation**

The routing decision's span_basis argues for the country convention's default start rule (1790, the year of the Revolutionary départements reform), since Yonne is not among the four enumerated departure cases (Belfort, Alsace-Lorraine départements, Corse split, overseas départements). But no FRA national polity row in this database covers 1790-1800 -- the earliest is FRA-1800-1871 -- and the containment gate rejects a container edge that falls outside the container's own span. I therefore set start_year to 1800, ten years later than the routing decision's proposed 1790, so that the container chain (FRA-1800-1871, FRA-1871-1919, FRA-1919-2025) tiles the entry's whole span with no gap. This exactly follows the precedent set by sibling entries FRA-18-1800-2025 (Cher), FRA-21-1800-2025 (Côte-d'Or) and FRA-77-1800-2025 (Seine-et-Marne), all of which face the identical 1790-vs-1800 mismatch and resolve it the same way. The uncovered 1790-1800 decade is recorded as an open question below.

### d-code-uses-insee-89-not-frc14

**Subunit code is the INSEE/ISO 3166-2 numeric code 89, not the routing decision's NUTS3 admin_name FRC14**

The routing decision labels this unit 'FRC14' (a Eurostat NUTS3 code for a Bourgogne-Franche-Comté département) and its unit_id 'FRA-FRC14'. Following the precedent set by FRA-18-1800-2025 (Cher, INSEE 18), FRA-21-1800-2025 (Côte-d'Or, INSEE 21) and FRA-77-1800-2025 (Seine-et-Marne), I used the INSEE/ISO 3166-2:FR two-digit numeric code 89 for Yonne rather than the NUTS3 code, since 89 is the identifier a reader recognises from French postcodes (89xxx), car plates, and INSEE statistical tables, whereas FRC14 is not in ordinary public use. This gives the code FRA-89-1800-2025, matching the dominant <ISO3>-<SUBUNIT>-<start>-<end> pattern with a subunit token a reader can actually place.

### d-polygon-unassigned-not-proxy

**Polygon left unassigned rather than proxied from the national polygon or a neighbouring département**

The routing decision's polygon_route is none_available / new_source_needed: no registered source in scripts/sources.yaml digitises French départements at this resolution. gadm-4.1-adm1's local file is a curated 81-country subset that excludes France (even though GADM's global admin-1 release does cover French départements), and cshapes-2.0/cshapes-europe are country-level only. I did not substitute the national FRA polygon or a hand-drawn union as a stopgap proxy, because doing so would defeat this row's purpose, which is to isolate Yonne's own reporting territory from the national one. polygon_source is set to the 'none' sentinel already used by FRA-18-1800-2025, FRA-21-1800-2025, FRA-77-1800-2025, and other unassigned rows in this table.

## Open questions

### oq-pre-1800-gap-uncovered

**The 1790-1800 decade of Yonne's existence is not represented by this entry or any container**

Yonne was created in 1790 by the Revolutionary départements reform, carved from parts of the former provinces of Burgundy, Champagne, Île-de-France and Orléanais (roughly the Auxerrois, Sénonais, and parts of Nivernais). That is ten years before this entry's start_year of 1800. The gap exists because no FRA national polity row in this database covers 1790-1800 -- the earliest is FRA-1800-1871. If a future entry adds an FRA-1790-1800 (or similar) national row closing that gap, this entry's start_year should be pulled back to 1790 with a matching container edge and the polity_code updated to FRA-89-1790-2025. Until then, any data keyed to Yonne in 1790-1799 has nowhere to route. The same open question already exists on sibling entries FRA-18-1800-2025, FRA-21-1800-2025 and FRA-77-1800-2025, so a fix would likely apply to several France département rows at once.

### oq-departement-boundary-stability-unverified

**Yonne's boundary stability across 1800-2025 is asserted from general knowledge, not checked against a source**

The routing decision's span_basis argues Yonne is not among the four enumerated departure cases and so follows the unbroken-existence default rule, but this is general knowledge of French administrative geography rather than a cited source. Yonne's borders with Aube, Côte-d'Or, Nièvre, Loiret and Seine-et-Marne have not been checked here for any 19th- or 20th-century canton-transfer adjustments (this kind of boundary tweak is common in French administrative history and would not necessarily register as a change to the département's headline territory). When a polygon source is finally registered for this row, its boundary vintage should be checked against a specific year rather than assumed identical to the present-day shape across the whole 1800-2025 span.

### oq-nuts-vs-insee-code-mismatch

**The routing decision's admin_name (FRC14, a NUTS3 code) does not match the INSEE code (89) used as this entry's subunit identifier**

The decision this page implements labels the unit 'FRC14', a Eurostat NUTS3 statistical code for a Bourgogne-Franche-Comté département, while this entry uses INSEE/ISO 3166-2:FR numeric code 89 as the polity_code subunit (see decisions). I have treated FRC14 and INSEE 89 as denoting the same territory (Yonne) based on standard NUTS-to-département crosswalks, but this crosswalk has not been independently verified against an authoritative Eurostat correspondence table within this pipeline run. Bourgogne-Franche-Comté also contains Côte-d'Or, Nièvre, Saône-et-Loire, Doubs, Jura, Haute-Saône and Territoire de Belfort, several of which are NUTS3-adjacent in code order to FRC14; if the source data's FRC14 rows in fact refer to a different département in this region, this entry would be misrouted.
