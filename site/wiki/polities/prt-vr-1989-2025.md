# Vila Real (district/NUTS III region of Portugal)

## Summary

Vila Real is a district of northern Portugal (and, under the later NUTS classification, part of the Norte NUTS II region as a NUTS III unit), centered on the city of Vila Real in the Trás-os-Montes area near the Douro valley. This entry captures Vila Real as a subnational statistical reporting unit within Portugal from 1989 to the present, distinct from Portugal's other districts (Faro/PTFA, Aveiro/PTAV, Beja/PTBJ, Évora/PTEV, Guarda/PTGU, Leiria/PTLE, Braga/PTPG, etc.) which have each already been adjudicated as separate sibling polities in this same pipeline pass. `type: subnational` is used, not `national`, because Portugal's sovereignty is unaffected — Vila Real is one of eighteen mainland districts, and this row exists purely to carry data that a source measures at the district/NUTS III level rather than at the national level. The 1989 start (rather than the country's nominal 1986 subnational-reporting default) follows the pattern already set by the sibling district entries, on the reasoning that this is when Portugal's district-level statistical series actually became routable in practice, though this has not been independently re-verified for Vila Real specifically (see open questions).

**Why this entry exists.** Input data: the routing decision for unit PRT-PTVR (admin_name PT_VR, country Portugal) reports that under the current classification, 109 of this unit's 144 total data years (76% of its span) were marked unroutable prior to this fix, implying the underlying source(s) report values across a span at least from the mid-1880s through 2023, though the decision does not itemize exact source names, row counts, or which years carry values versus which are structurally absent. Previously matched to: nothing usable — the harness flagged that leaving 109 measured years with no polity was the defect being corrected; before this entry, Vila Real's reporting years within the 1989-2025 window (and the unresolved pre-1989 years) had no district-level home and would otherwise have been silently dropped or mis-attributed to the whole-country row PRT-1800-2025, which is roughly 22 times Vila Real's area and would badly dilute a district-specific measurement. What confirms distinctness: Vila Real is a standing, internationally recognized Portuguese administrative district and NUTS III unit, structurally identical in kind to the six sibling Portuguese districts (Aveiro, Beja, Évora, Guarda, Leiria, Braga) that this same pipeline pass already created as separate polities — its distinctness from the whole country and from those siblings is definitional (each is a disjoint, non-overlapping district), not something requiring an external cross-check the way a contested historical territory would.

## Decisions

### d-code-follows-iso3-subunit-pattern

**Code PRT-VR-1989-2025 follows the dominant ISO3-SUBUNIT-start-end pattern**

Vila Real is an ordinary Portuguese administrative district (NUTS III region), not a historical territory with a name of its own like Alaska Territory or Hyderabad, so it takes the dominant 57/66 pattern rather than a bespoke code. The subunit token VR matches the convention already used by sibling districts routed in prior verdicts (PTAV, PTBJ, PTEV, PTGU, PTLE, PTPG all shortened to two-to-three letter district codes), giving PRT-VR-1989-2025. The country PRT has no existing subnational codes, so there is no established sibling precedent inside this repo to contradict, but the routing decision's own list of siblings (PTAV/PTBJ/PTEV/PTGU/PTLE/PTPG) confirms the abbreviated-token convention this code follows.

### d-start-year-1989-not-1986

**Start year 1989 follows sibling verdicts over the country's nominal 1986 default**

The routing decision explicitly notes a tension: the country convention's stated default subnational start is 1986, but every already-adjudicated sibling district (PTAV, PTBJ, PTEV, PTGU, PTLE, PTPG) was started at 1989, matching when Portugal's district-level statistical reporting under the NUTS system became routable in practice. To keep this new entry consistent with its siblings rather than introduce a one-off inconsistency, 1989 was kept as the start year, per the routing decision's own span_basis field. This is flagged as an open question below since it was not independently re-verified against Vila Real's own administrative record.

## Open questions

### oq-polygon-unfetched-gadm-portugal

**GADM 4.1 adm1 file for Portugal has not been fetched**

The locally cached GADM 4.1 adm1 dataset used elsewhere in this repo is a curated 81-country subset that excludes Portugal entirely. GADM as a global project does publish Portuguese district-level (NUTS III-equivalent) boundaries, so the correct remedy is to fetch the full/global GADM 4.1 adm1 file and extract the Vila Real feature (likely GID_1 code matching PRT.<n>_1), not to construct a substitute polygon. Until that fetch happens, polygon_status stays unassigned and polygon_feature_id stays null. Whoever performs the fetch should also confirm the feature naming/GID convention against whichever features get assigned to the other Portuguese sibling districts, so all PRT subnational rows draw from a single consistent GADM extraction rather than mismatched vintages.

### oq-1989-start-not-independently-verified

**1989 start year for Vila Real reporting is inferred from siblings, not confirmed**

The proposed start_year of 1989 comes from matching the pattern set by other already-adjudicated Portuguese district siblings (PTAV, PTBJ, PTEV, PTGU, PTLE, PTPG), not from an independent check of when Vila Real district itself began appearing in subnational statistical series, or of Vila Real's own administrative history (e.g., whether its boundaries as a NUTS III unit were stable back to 1989, or were redrawn in a later NUTS revision). If Vila Real's own data first becomes routable at a different year than its siblings, or if a NUTS boundary revision moved municipalities into or out of the Vila Real region after 1989, this start year and the polygon vintage would both need revision.
