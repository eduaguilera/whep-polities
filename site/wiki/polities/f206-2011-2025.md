# Sudan and South Sudan (combined reporting)

## Summary

A **reporting unit, not a state.** No entity governed Sudan and South Sudan jointly after South
Sudan's independence on 9 July 2011. This row exists because a consumer sums the two and needs
something truthful to attribute that sum to.

## Why this entry exists

`eduaguilera/whep` folds FAOSTAT areas **276 Sudan** and **277 South Sudan** into one FABIO
reporting bucket (region 206) and sums them, so a 2015 bucket value covers **both** territories —
measured on FAOSTAT production for 2015, Sudan 53,124,088 t plus South Sudan 14,876,146 t as one
figure. Its year-aware lookup found no post-2011 row for area 206, fell back to the nearest period,
and labelled that sum **`SUD-1956-2011`** — a polity that ended in 2011. The extent was right and
the period was not, and nothing in this database meant "Sudan and South Sudan, 2011 onward"
(issue 139).

## The decision this row makes, and the evidence for it

Issue 139 asked whether such an entity belongs here at all, or is a consumer's aggregation artefact
that belongs downstream. It raised two doubts, **and measuring both settles them the same way.**

### "This entity would be live at the same time as both its members, which F237/F249 never are"

`F237-1954-1975` (Vietnam, combined reporting) is live **1954-1975** and so are both of its members:

```
F237-1954-1975  1954-1975  aggregate
DRV-1954-1975   1954-1975  national     coexists for the whole span
RVN-1954-1975   1954-1975  national     coexists for the whole span
```

So the cited precedent does exactly what the issue feared. It is not even unusual here: ten more
aggregates coexist with their own members, including `RLAM-1850-2025`, `ROW-1850-2025`,
`MASG-1946-1963`, `SYL-1944-1953`, `TTPI-1947-1994`, `BWI-1833-1962`, `BLI-1833-1960`,
`LBY-1949-1951` and `IDN-1949-1969`. `validate_spatial_containment`'s `LEGITIMATE_CONTAINERS`
exists to record precisely that relationship.

### "For Vietnam and Yemen it is FAOSTAT that reports the combination; for Sudan it is whep's own FABIO regionalisation"

True, and it does not distinguish the cases, because **this database already carries seven
identities that exist only because FABIO folds**: `ROW-1850-2025`, `RAFR`, `RASI`, `REUR`, `RLAM`,
`RNAM` and `ROCE`. None of them is a FAOSTAT reporting unit; each is a downstream regionalisation
given a territorial identity here so the ground it covers can be named. A Sudan-plus-South-Sudan
bucket is the same object.

So the answer is issue 139's option (1): the identity belongs here.

## Territorial extent

**Polygon:** constructed — the union of the two members' own CShapes features, 625 and 626, so the
aggregate cannot drift from its parts.

```
SDN-2011-2025           1,859,556 km²   measured
SSD-2011-2025             627,258 km²   measured
union                   2,486,805 km²   measured
SUD-1956-2011           2,486,812 km²   ratio 1.0000
declared                2,505,813 km²   Sudan 1,861,484 + South Sudan 644,329, official
```

Agreement with unified Sudan to four decimal places is the check that matters: this row exists to
describe exactly the territory `SUD-1956-2011` described, for the years after it stopped existing.

**The declared area is the sum of the two OFFICIAL land areas, not the measured union**, and the
difference is deliberate. My first version declared 2,486,805 — the union's own measurement — and
`validate_polygons`' A2 check immediately reported it as self-referential: a declared figure copied
off the geometry it is supposed to test cannot disagree with it, which is the tautology issue 195
measures at 104 of 209 rows. Declaring 1,861,484 + 644,329 instead gives check A something
independent to compare, and the resulting **0.76%** divergence is a real measurement of how far
CShapes sits from the two gazetteers.

The 8.9 km² the two members intersect is sliver along their shared boundary from simplifying each
independently — the artefact documented for `TRP`/`CYR` in issue 156 — and the union absorbs it.

## `iso3: NA`, deliberately, against `F237`/`F249`'s practice

`F237` carries `VNM` and `F249` carries `YEM`, so the F-convention would suggest `SDN` here. It is
blank instead, following `SYL-1944-1953`, the other two-member union.

**Giving it `SDN` would assert that an ISO3-keyed lookup for Sudan may return the two-country sum —
which is the exact mislabelling issue 139 reports, moved from the period to the code.** This entity
is not Sudan. It is reached by FAOSTAT area 206, not by an ISO3 join, so nothing needs the code.

## What this row does NOT do

**It adds no row to `faostat_area_polity_map.csv`.** FAOSTAT stops reporting area 206 in 2011 and
does not resume; the post-2011 combination is FABIO's. Adding a map row would assert a FAOSTAT
reporting practice that does not exist. The map stays as it is, and whep points its own bucket at
this polity — which is the division of labour issue 139 asks for.

## Predecessors and successors

`predecessor: [SUD-1956-2011]`, and **`SUD-1956-2011` deliberately does NOT name this row back.**

> **That reverse edge was added on 2026-08-13 and removed the same day, because it broke a
> downstream invariant and violated a convention this database already had.**
>
> whep's `polity_bucket_coverage()` classifies each folded reporting bucket, and its
> `.bucket_is_predecessor()` test is an **exact set equality**:
>
> ```r
> key <- successors$successor_key[match(bucket_code, successors$polity_code)]
> ended & !is.na(key) & key == member_codes
> ```
>
> `SUD-1956-2011`'s successors were exactly `SDN-2011-2025, SSD-2011-2025` — the bucket's two
> members — so bucket 206 classified as `predecessor`: honestly labelled with the ended state that
> preceded both. Adding a third successor made the key `F206, SDN, SSD`, which no longer equals the
> members, so all 14 year-rows fell through to **`partial`** — the class whose own test says *"if
> any bucket ever starts folding several territories under a polity covering only some of them,
> this is where it shows up instead of shipping."* The invariant was right and the edit was wrong.
>
> **And the convention was already established here.** Of the six reporting aggregates in this
> database — `SYL-1944-1953`, `F237-1954-1975`, `F249-1918-1990`, `ROW-1850-2025`,
> `RLAM-1850-2025`, `MASG-1946-1963` — **not one is named as a successor by any page.** Zero. An
> aggregate may *declare* a predecessor (`F237` declares `VNM-1887-1954`), but nothing declares an
> aggregate as its successor, because an aggregate is not what a territory became. Putting one
> there overloads `successor:` to mean "related to", which is the error PR 135 removed from
> Greenland and Iceland.
>
> So this row keeps its `predecessor:` and the edge stays one-directional, exactly as `F237`'s
> does. That raises `validate_chain_integrity`'s predecessor-only count by one, and the pin was
> raised with this reason recorded rather than treated as a regression.

`successor:` is empty because this row runs to the 2025 ceiling and a live entity has nothing after
it — signal D fails on a live ceiling row that declares one.

## Contradictions

It contains both its members, by construction and on purpose. Any spatial or area-weighted use must
pick one level: this row, or `SDN` + `SSD`. Summing all three triple-counts the ground, which is the
same caveat `FID-1887-1954` carries over Indochina.

## Open questions

### oq-f206-composition-not-expressible

Nothing in the schema records that this row **is** `SDN-2011-2025` plus `SSD-2011-2025`. The
`predecessor`/`successor` fields express chronology, not composition, so a consumer cannot discover
the membership from the data — only from this page. That is the gap issue 138 finds for
`BLX-1850-1999` and issue 48 for aggregate components, and it applies to every aggregate here.
