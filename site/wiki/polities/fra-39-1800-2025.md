# Jura

## Summary

This entry represents Jura, a French département in the Bourgogne-Franche-Comté region, named for the Jura Mountains that form its eastern border with Switzerland, centred on its prefecture Lons-le-Saunier and running from the Bresse plain in the west up through the wine country around Arbois to the forested Jura massif along the Swiss frontier. It is coded as a `subnational` polity because a département is an administrative subdivision of France, not a sovereign state or a distinct internationally-recognised territory -- France's sovereignty over this area is continuous and undisputed throughout the entry's span, and the national FRA rows in this table already carry that sovereignty claim for the whole country. This row exists solely to carry a *sub-national reporting territory*: statistics keyed to "Jura" or its Eurostat NUTS3 code FRC22 specifically, as opposed to all-France totals, need somewhere to route that isn't the national polygon. The entry follows the country convention's default start rule (1790, the year of the Revolutionary départements reform) as adjusted here to 1800 to match the earliest available French national container row (see decisions), and runs to the open end_year 2025 since the département remains an active administrative unit of France today with no successor.

**Why this entry exists.** This page implements the routing decision for unit FRA-FRC22 (admin_name "FRC22", country France), which resolved via create_new because no existing FRA polity IS this territory -- the national FRA rows (FRA-1800-1871, FRA-1871-1919, FRA-1919-2025) describe the whole country, and a département cannot be represented by its country's row; the only iso3-FRA candidates the routing decision considered are all national-level rows spanning different Alsace-Lorraine configurations, which contain but are not equal to Jura. Before this decision, any data keyed to Jura specifically was, by construction of the routing pipeline, unmatched rather than misrouted -- match_existing was excluded outright since no existing row's territory equals this département's. What confirms Jura as a distinct, statistically-reported entity rather than an arbitrary subdivision is that it is one of the original Revolutionary départements of 1790 and has been tabulated in French statistical yearbooks (INSEE and predecessors, and Eurostat's NUTS3 series under FRC22) as a discrete unit under code 39 ever since -- the same status INSEE gives every other département, and the same status already recognised for the sibling FRA département entries in this table (Cher, Côte-d'Or, Seine-et-Marne, and others). This entry's span (1790-2025 per the routing decision, adjusted here to 1800-2025, see decisions) covers the full administrative existence rather than a narrower data span, so a single create_new polity suffices.

## Territorial extent

Polygon status: Not yet assigned. No polygon available in the GeoPackage for this period. The routing decision already established this is a `new_source_needed` case: no source registered in scripts/sources.yaml digitises French départements at this resolution. gadm-4.1-adm1's local file is a curated subset of 81 countries that omits France entirely (even though GADM's global release does cover French départements at admin-1, per the decision's 0-match note); cshapes-2.0 and cshapes-europe are country-level only and cannot supply a sub-national boundary. The standard remedy would be to register GADM's global admin-2 layer or French IGN's ADMIN-EXPRESS product, neither of which is on disk in this repository today.

Territory description: Jura covers roughly 4,999 km² in the southeastern part of Bourgogne-Franche-Comté, bordering Doubs to the north, Haute-Saône and Saône-et-Loire to the west, Ain to the south, and Switzerland (cantons of Vaud, Neuchâtel and Jura) to the east. Its prefecture is Lons-le-Saunier; it spans the flat Bresse plain in the west, the vineyard country around Arbois and Château-Chalon, and the forested Jura mountain massif rising toward the Swiss border. This description is drawn from present-day knowledge of the département's location and standard reference figures for its area, not measured from any polygon attached to this entry, since none is yet assigned.

## Decisions

### d-start-year-1800-not-1790

**start_year set to 1800, not the routing decision's proposed 1790, to match the earliest available FRA container row**

The routing decision's span_basis argues for 1790 under the country convention's default start rule, since Jura is not one of the four enumerated departures (Belfort, Alsace-Lorraine, Corsica split, overseas départements). But no FRA national polity row in this database covers 1790-1800 -- the earliest is FRA-1800-1871 -- and the containment gate rejects a container edge that falls outside either party's own span. I therefore set start_year to 1800 to match the earliest FRA container, exactly as the sibling FRA département entries (FRA-18-1800-2025 Cher, FRA-21-1800-2025 Côte-d'Or, FRA-77-1800-2025 Seine-et-Marne, and others) already do, rather than leaving a decade uncontained. The polity_code year (1800) equals the frontmatter start_year, satisfying the code/frontmatter equality gate. The 1790-1800 gap is recorded as an open question below, matching every other FRA département sibling.

### d-subunit-code-insee-39-not-frc22

**Subunit code is the INSEE/ISO 3166-2 numeric code 39, not the routing decision's NUTS3 admin_name FRC22**

The routing decision labels this unit 'FRC22' (a Eurostat NUTS3 code for a Bourgogne-Franche-Comté département) and its unit_id 'FRA-FRC22'. Following the precedent set by every existing FRA département sibling (FRA-18 Cher, FRA-21 Côte-d'Or, FRA-25 Doubs, FRA-71 Saône-et-Loire, etc.), I used the INSEE/ISO 3166-2:FR two-digit numeric code 39 for Jura rather than the NUTS3 code, since 39 is the identifier a reader recognises from French postcodes (39xxx) and car plates, whereas FRC22 is not in ordinary public use. This gives the code FRA-39-1800-2025, matching the dominant <ISO3>-<SUBUNIT>-<start>-<end> pattern with a subunit token a reader can actually place, and keeps the France subnational family internally consistent rather than mixing NUTS and INSEE identifiers across siblings.

### d-polygon-unassigned-not-proxy

**Polygon left unassigned rather than proxied from the national polygon or a neighbouring département**

The routing decision's polygon_route is new_source_needed: no registered source in scripts/sources.yaml digitises French départements at this resolution. gadm-4.1-adm1's local file is a curated 81-country subset that excludes France entirely (0 GADM adm1 matches for FRA, per the decision), and cshapes-2.0/cshapes-europe are country-level only. I did not substitute the national FRA polygon or a hand-drawn union as a stopgap proxy, because doing so would defeat this row's purpose, which is to isolate Jura's own reporting territory from the national one, and would misrepresent an 18,000+ km² national shape as an approximately 5,000 km² département. polygon_source is set to the 'none' sentinel already used by the other unassigned FRA département rows in this table.

## Open questions

### oq-pre-1800-gap-uncovered

**The 1790-1800 decade of Jura's existence is not represented by this entry or any container**

Jura was created in 1790 by the Revolutionary départements reform, carved from the former province of Franche-Comté (with small portions of the former Bailliage de Lons-le-Saunier and adjoining territory). That is ten years before this entry's start_year of 1800. The gap exists because no FRA national polity row in this database covers 1790-1800 -- the earliest is FRA-1800-1871. If a future entry adds an FRA-1790-1800 (or similar) national row closing that gap, this entry's start_year should be pulled back to 1790 with a matching container edge and the polity_code updated to FRA-39-1790-2025. Until then, any data keyed to Jura in 1790-1799 has nowhere to route. The same open question already exists on the sibling entries (Côte-d'Or, Cher, Seine-et-Marne, etc.), so a fix would likely apply to several France département rows at once.

### oq-departement-boundary-stability-unverified

**Jura's boundary stability across 1800-2025 is asserted from general knowledge, not checked against a source**

The routing decision's span_basis argues Jura is not among the four enumerated departure cases and so follows the unbroken-existence default rule, but this is general knowledge of French administrative geography rather than a cited source. Jura's borders with Doubs, Haute-Saône, Saône-et-Loire, Ain and Switzerland (the cantons of Vaud, Neuchâtel and Jura) have not been checked here for any 19th- or 20th-century commune-transfer adjustments; cantonal reorganisations of this kind are common in French administrative history and would not necessarily register as a change to the département's headline territory. When a polygon source is finally registered for this row, its boundary vintage should be checked against a specific year rather than assumed identical to the present-day shape across the whole 1800-2025 span.

### oq-nuts-vs-insee-code-mismatch

**The routing decision's admin_name (FRC22, a NUTS3 code) does not match the INSEE code (39) used as this entry's subunit identifier**

The decision this page implements labels the unit 'FRC22', a Eurostat NUTS3 statistical code for a Bourgogne-Franche-Comté département, while this entry uses INSEE/ISO 3166-2:FR numeric code 39 as the polity_code subunit (see decisions). I have treated FRC22 and INSEE 39 as denoting the same territory (Jura) based on standard NUTS-to-département crosswalks, but this crosswalk has not been independently verified against an authoritative Eurostat correspondence table within this pipeline run. Bourgogne-Franche-Comté also contains Côte-d'Or, Nièvre, Saône-et-Loire, Yonne, Doubs, Haute-Saône and Territoire de Belfort, several of which are NUTS3-adjacent in code order to FRC22; if the source data's FRC22 rows in fact refer to a different département in this region, this entry would be misrouted.
